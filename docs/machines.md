# Subjects that carry their own memory type

**Machines in the degenerate and trivial-witness checks** (`LeanIntent.CoveredMachine`, `LeanIntent.MachineVerdicts`, `LeanIntent.MachineWitnessVerdicts`): for a subject type whose values carry their own memory type, an initial memory and a step from a memory and an input to an output and the next memory, such as an agent with its own memory, a closed class of degenerate subjects and a closed class of trivial witnesses, each fixed by the subject's type and never chosen per record or pair, stated apart from the lists that compute them, with a proved verdict on each member, as [the degenerate check](degenerate-subjects.md) and [the trivial-witness check](trivial-witnesses.md) give for the types their codes cover. Among the trivial witnesses are those the method names for an agent with memory: one whose actions are fixed in advance (an open-loop agent, such as a clocked script), one that ignores its input, and the vacuous witness.

Modules: `LeanIntent/Machines.lean` (machines, the reading of a subject through its behaviour, and both checks), `LeanIntent/MachineDeclared/Handler.lean` (the deriving handler for the structures a project declares as machines), `LeanIntent/MachineDeclared.lean` (its registration), `LeanIntent/CodeAudit.lean` (the audit, which reads machine attestations as well as declared types' codes) and `LeanIntent/Loaded.lean` (the guard refusing an environment whose extensions' state is not loaded).

**Complete in this version:** the library's own machines (`LeanIntent.Machine`), the coverage of structures a project declares with the machine's shape through `deriving LeanIntent.CoveredMachine` (at universe level zero and naming the memory field directly in the step, as stated under [The types covered](#the-types-covered)), both checks over such types with the theorems that fix their classes and clock coverage (`machineTimed_mem_of_namedClock`), and the audit of the attestations the handler writes (#43).

**Not yet built**, a separate issue of this repository: covering subject types in a higher universe that do not have the machine's shape, such as a structure that carries several types (#76).

## Why a code is not enough

The two checks cover a subject type only where Lean's instance resolution finds a code for it (`LeanIntent.Covered`), and every code denotes a type of `Type`. A value that carries a type of its own, such as an agent whose field `Memory : Type` holds what it retains, lives in `Type 1`, so no code denotes its type, and Lean refuses to synthesize `Covered` for it. Such an agent's contract with its world is exactly where the trivial-witness attack matters: in a world whose goals are feasible exactly when a clocked script, an agent whose memory is a step counter and which reads nothing it sees, achieves them, a pair that asks for each goal alone is met by such a script, and the obligation of that pair is then no evidence that the agent uses what it sees.

## The types covered

A type `W : Type 1` is covered as a machine (`CoveredMachine W`) when Lean's instance resolution finds, from `W` alone, an input type `In` and an output type `Out`, each with a code (`LeanIntent.HasCode`), and the isomorphism through which `W` stands for `Machine In Out`, the library's machines from `In` to `Out`, with the proof that it is the one the library fixes (`LeanIntent.Machine.Stands`):

- `Machine I O` itself, a structure of three fields, `Memory : Type`, `initial : Memory` and `step : Memory → I → O × Memory`, through the identity (`MachineIso.refl`, `Machine.Stands.self`), for every `I` and `O` with codes;
- a Lean `structure` a project declares (not a plain `inductive`) whose constructor has no indices, is neither recursive nor of a mutual declaration, is not unsafe, lives in `Type 1` when its universe parameters are specialized to level zero (covering only the level-zero instantiation of a universe-polymorphic structure), and has exactly three fields: first a type of `Type`, the memory; one of the other two whose type reduces reducibly to the memory field, the initial memory; and the other a step whose type reduces reducibly to `memory → input → output × memory` naming the memory field directly as its first argument and second pair component (not through a reducible alias such as `abbrev S (M : Type) := M`), where the input and output types are types of `Type` that name no field. The fields' names and the order of the last two are the project's, and its parameters may be types or values, such as the interface an agent is indexed by. `deriving LeanIntent.CoveredMachine` (or `deriving instance LeanIntent.CoveredMachine for T`) reads the declaration through Lean's environment (`MachineDeclared.readRoles`) and writes the isomorphism that takes each field to the machine's field of the same role (`MachineDeclared.mkIso`, `instCoveredMachineT.iso`), the attestation through the private constructor `Machine.Stands.decl` (`instCoveredMachineT.stands`), and the `CoveredMachine` instance (`MachineDeclared.mkCoveredMachine`), for every value of the parameters at which the input and output types have codes (`LeanIntent.MachineDeclared.Handler`; importing `LeanIntent.MachineDeclared` registers the handler). The handler clears enclosing section `variable`/`include`/`omit`/`universe` scope entries inside `withScope`, checks duplicate coverage with the `[HasCode In]` and `[HasCode Out]` assumptions in scope before adding declarations, runs `MachineDeclared.checkAttestation` inside `withoutExporting` on what it wrote and fails rather than write an attestation the audit refuses, writes exposed definitions in `module` files (or private `noncomputable` ones for non-public structures, refusing mixed public/non-public `deriving` commands), and guards every monadic entry point with `LeanIntent.asking`/`askingIn` while `MachineDeclared.refusal?` requires `LeanIntent.Loaded env` ([ADR-0006](adr/0006-declared-type-coding-and-code-audit-internals.md), [ADR-0009](adr/0009-environment-extension-loading-and-reader-guards.md)).

Every other type in a higher universe has no instance, so Lean reports that it cannot synthesize `CoveredMachine W` and no verdict about it can be stated: a plain `inductive` type not declared as a `structure`, a structure that carries several types or a type and other fields, one whose memory is in `Type 1` or above, a universe-polymorphic machine structure instantiated at universe levels above zero (since `MachineDeclared.mkCoveredMachine` specializes universe parameters to level zero), a structure whose step names its memory field only through a reducible alias such as `abbrev S (M : Type) := M` (which `MachineDeclared.readRoles` does not unfold inside the step's domain or pair return), a step with no input or no output, a field that is a function to types, and a structure that reaches the three fields only through a parent structure it extends. The handler refuses each such declaration (`MachineDeclared.refusal?`, `MachineDeclared.readRoles`) and says why, and also refuses `LeanIntent.Machine` itself and any type already covered as a machine. A closed class needs a reading of each subject that its type fixes; a machine has one, its behaviour, and none is established yet for an arbitrary structure that carries a type, so covering further shapes is separate work (#76).

## The reading of a subject: its behaviour

A machine's behaviour (`Machine.behaviour`) is its output on an input after each history of earlier inputs, a function of type `List I → I → O`, which the codes cover. Every such function is the behaviour of a machine, whose memory is the history (`Machine.ofBehaviour`, `Machine.behaviour_ofBehaviour`), and a machine's memory after a history is the fold of its step over it (`Machine.memoryAfter`), so two machines with one behaviour give the same outputs on every sequence of inputs, whatever their memory types. A subject `w` of `W` is read as the behaviour of the machine the isomorphism takes it to (`CoveredMachine.behaviourOf`), and each class of `W` is the class of the behaviour type, `CoveredMachine.Behaviour W`, with each member standing for every subject of `W` whose behaviour that member describes.

No member fixes a memory type. A member admits a subject by its behaviour alone (`Degenerate.isMachine_congr`, `MachineWitness.admits_congr`), and the subject that is a machine of any memory type is admitted exactly when that machine's behaviour is (`Degenerate.isMachine_inv_iff`). So a record or pair that also constrains the memory, such as one bounding its number of values, meets a member whenever some subject of any memory type with that behaviour meets it. A class whose members were subjects of one memory type, such as clocked scripts whose memory is a number, would miss a script whose memory is a counter of four values for a pair that bounds the memory to four.

## The degenerate class

`machineDegenerate W` is the degenerate class of the behaviour type (`LeanIntent.degenerate`): the machine whose output is one value whatever its inputs, at each value the rule `Ty.Small` admits, or as one member for the others of a type too large to list, the empty output among them; and the machine whose output is what it was given—its current input, its history of earlier inputs, or, where its output is a function, that function's argument; what a function among them returns (such as calling a function-valued input on a source); or a part of any of these: a projection. `Degenerate.IsMachine d w` states that the behaviour of `w` is one `d` stands for. `MachineVerdicts r bs` is the check: its goals (`machineVerdicts`, built by `truthGoals`, `goals_truthGoals`) state, for each member in order, that some subject it stands for meets `r` where `bs` says `true` and that none does where `bs` says `false` (`machineVerdicts_correct`, against `intendedMachineVerdicts`). `machineMetBy W bs` lists the members reported (`mem_machineMetBy`), `machineConsequence W i` builds the `Consequence` of kind possibility over `W` for the `i`-th member of `machineDegenerate W` with a distinct numbered name (`#1: ...`, `#2: ...`, fixed by its position in `machineDegenerate W`, `Degenerate.machineNameAt`, `machineConsequence_name_inj`, `machineConsequence_eq_of_name_eq`, `machineConsequence_name_ne_restatement`), `machinePossibilities h` reports each met member in order (`mem_machinePossibilities`, `machinePossibilities_holdsOf`, `map_holds_machinePossibilities`) with pairwise distinct selectable names (`machinePossibilities_names_nodup`) such that looking up any reported consequence by name recovers that exact consequence and predicate (`find?_machinePossibilities`, `find?_map_machinePossibilities`), a declined one is kept by exactly the revisions no subject of the member meets (`machineDeclined_keptBy_iff`), and verdicts that report nothing refute every subject of every member, of every memory type (`not_meets_of_machineMetBy_eq_nil`).

## The trivial witnesses

`machineWitnesses W` holds the trivial witnesses of the behaviour type ([the trivial-witness check](trivial-witnesses.md)), each read through the behaviour (`.behaviour t`), and two members of machines' own (`LeanIntent.MachineWitness`):

| Member | The strategies it stands for | Theorem |
|---|---|---|
| `.behaviour .vacuous` | Every strategy | `MachineWitness.vacuous_meets_iff` |
| `.behaviour .table` | At each input, a subject whose behaviour is a constant of the code's function, fixed for that input | `MachineWitness.meets_iff_strategy`, `MachineWitness.constantAction_meets_of_table` |
| `.behaviour (.blind i)` | At each input, a subject whose behaviour does not read its argument at `i`: at `0` its history, a reactive agent, and at `1` its current input | `blindTo_history_iff`, `blindTo_input_iff` |
| `.behaviour (.fixed d)` | One subject whose behaviour the degenerate member `d` stands for, at every input | `MachineWitness.fixed_meets_iff` |
| `.behaviour (.timed k)` | At each input, a subject whose behaviour reads only the clock part `k`: among them the history's length whenever it does not determine the entire flattened argument tuple of `sig W` (a script of timed actions constant in any further flattened output arguments), and what each input holds where the input's type has a clock part | `MachineWitness.meets_iff_strategy`, `machineTimed_mem_of_namedClock` |
| `.constantAction` | At each input, a subject that gives one output whatever its inputs and history, fixed for that input: one that ignores its input (`Machine.ConstantAction`) | `MachineWitness.constantAction_meets_of_met`, `MachineWitness.constantAction_meets_of_table`, `MachineWitness.constantAction_meets_of_vacuous` |
| `.fixedInAdvance` | At each input, a subject whose outputs are fixed in advance, a function of the number of inputs it has had (`Machine.FixedInAdvance`): an open-loop agent (`Machine.OpenLoop`), whose memory advances and whose output is chosen without reading its input, such as a clocked script (`Machine.clockedScript`) | `MachineWitness.fixedInAdvance_meets_iff_scripts`, `MachineWitness.fixedInAdvance_meets_of_openLoop`, `MachineWitness.fixedInAdvance_meets_of_clockedScripts`, `MachineWitness.fixedInAdvance_meets_of_constantAction` |

The two members of machines' own are in the class whatever the input and output types. The behaviour type's class already holds the script on the history's length and the table of constants where the output is no function and the input has two values or more; but where the output is a function, the behaviour's code flattens its arguments into further arguments of `sig W`, so `.behaviour .table` and the history-length `.behaviour (.timed k)` hold only behaviours constant in those flattened output arguments too (unlike `.constantAction` and `.fixedInAdvance`, which allow any value of `m.Out`—including a non-constant function—fixed per pair input or per step), and the history's length is omitted from the behaviour type's clocks exactly when it determines the entire flattened argument tuple of `sig W` (that is, when `m.In` and every flattened argument of `m.Out`, if any, have one value, as in `Machine Unit Bool` or `Machine Unit (Unit → Bool)`; for `Machine Unit (Bool → Bool)`, two flattened tuples of the same history length still differ in the output's `Bool` argument, so the timed member qualifies). A member of machines' own and a member of the behaviour type's class can stand for the same strategies; their verdicts then agree.

`mem_machineWitnesses_iff` states the class apart from the list that computes it, and `length_machineWitnesses` its size, the behaviour type's members and two. `Pair.MachineMetTrivially` states, over strategies and apart from the class, that some trivial witness meets the pair, and `machineMetTrivially_iff` equates it with some member of the class meeting it. `MachineWitnessVerdicts q bs` is the check (`machineWitnessVerdicts_correct`, against `intendedMachineWitnessVerdicts`), enforcing `(sig W).strayClock = false` (combining `Ty.strayClock` and `Ty.clocksRead` on every argument of the behaviour type, `not_machineWitnessVerdicts_of_strayClock`): because argument `0` of `Behaviour W = List m.In → m.In → m.Out` is `List m.In`, a `LeanIntent.Clock` reachable in `m.In` is inside a list where no clock part reaches it and is refused, whereas under proved verdicts every `LeanIntent.Clock` reachable in an argument of `sig W` (such as a flattened function argument of `m.Out`) is guaranteed to be read at that exact argument position by a `.behaviour (.timed ...)` member of `machineWitnesses W` (`machineTimed_mem_of_namedClock`). `machineReported W bs` lists the members reported, empty exactly when no trivial witness meets the pair (`mem_machineReported`, `machineReported_eq_nil_iff`). No member meets a pair with an admitted input that no subject serves (`MachineWitness.not_meets_of_unserved`), and the class takes no pair and no parameter but `W`.

## Worked example

[`LeanIntentExamples/Machines.lean`](../LeanIntentExamples/Machines.lean): an agent a project declares, with its own memory type, on a ring of four positions where all it sees is where it is, and whose record asks it to be at `0` after three steps from every start. Each start alone is reached by the clocked script that steps forward as many times as that start needs, so the per-start pair is met by `.fixedInAdvance` and the check reports it (`perStart_witnesses`, `perStart_fixedInAdvance_reported`); no agent that takes one action throughout reaches `0` from position `2`. The pair whose only input is trivial is met by no agent whose first action does not read what it sees, so by no script or constant, and by the agent that steps forward exactly when it is not at `0`, which keeps no memory (`whole_witnesses`). A pair that also bounds the memory to four values is still met by `.fixedInAdvance`, through a script whose memory is a counter round the ring (`perStartSmall_fixedInAdvance`). The degenerate check refutes both constant agents for the record (`homing_verdicts`) and reports the agent that never moves for a record asking only that an agent at `0` stay there (`stayHome_verdicts`, `stayHome_possibilities`). The library's own machines are covered through the identity (`machineOf_machine`), a structure with a value parameter and its fields in another order by the handler that covers the agent (`Indexed`, `indexed_witnesses_length`), and a `private` structure in a `module` file under private names in its own module only (`Hidden`, `hidden_machineOf`).

## What is trusted

Besides [what the README lists](../README.md#what-is-trusted), [what the degenerate check trusts](degenerate-subjects.md#what-is-trusted) and [what the trivial-witness check trusts](trivial-witnesses.md#what-is-trusted) about the codes of covered types, the classes of the behaviour type and clock detection:

- That the coverage of a structure a project declares is the one its declaration fixes. That the deriving handler reads the constructor's fields and their roles from Lean's environment (`MachineDeclared.readRoles`) is its own code, not checked by Lean's kernel; the kernel checks that the isomorphism it writes is one. That nothing else applies the private constructor of `Machine.Stands` is decided by the audit of declared types' codes for each declaration it accepts (`LeanIntent.CodeAudit`), which reads this kind of attestation in every environment that declares `Machine.Stands`, the only ones where a declaration can name that constructor (`LeanIntent.CodeAudit.kinds`), and trusted of every declaration a project does not audit. The audit reads each attestation through `MachineDeclared.checkAttestation`, which reads the roles through the handler's own function and compares by Lean's kernel the type, the input and output types and where the isomorphism takes the constructor applied to fields of the three roles; that this fixes the isomorphism, since a map from a structure is fixed by where it takes its constructor, by the structure's eta rule, and an isomorphism by its forward map, is argued, not proved. That the declarations Lean `v4.36.0` generates for `Machine.Stands` that name its constructors are among those `CodeAudit.generatedBy` lists (`rec`, `casesOn`, `recOn`, and `below` where present) is observed of that release; a release that generates another makes the audit refuse rather than accept.
- That a subject is what its behaviour shows of it, for the classes: two subjects with one behaviour are subjects of the same members, so a subject that keeps what it sees and never uses it is a member of `.fixedInAdvance`, and a record that constrains how a subject computes, not what it outputs, is checked only through the subjects of each behaviour, all of which the member quantifies over.
- That a witness the class leaves out is not one the owner needed to see. Besides what the trivial-witness check leaves out of the behaviour type's class, the class holds no member for a subject whose output reads the history only through its length and also reads the current input, such as an agent whose memory advances without reading what it sees while its action does, nor one for a subject whose output reads one part of an input and the rest of its history; the agents' attack on each pair, as the method makes it, still covers them.
- That every record or pair about a type covered as a machine has its verdicts stated: Lean refuses to state verdicts about a type with no instance, but nothing in the library requires them, as nothing requires O1 to O5.
