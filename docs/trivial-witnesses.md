# The trivial witnesses of a pair

**The trivial-witness check** (`LeanIntent.witnesses`, `LeanIntent.WitnessVerdicts`): for a precondition-postcondition pair about a subject type the library's codes cover, a closed class of trivial witnesses fixed by the pair's subject type and never chosen per pair (any subject at all, a table fixed to each input in advance, at each input a subject that does not read one of its arguments, and one degenerate subject at every input), with a proved verdict for each on whether it meets the pair, so that one that does is reported rather than missed.

Module: `LeanIntent/TrivialWitnesses.lean`.

**Complete in this version:** the class with the theorems that fix it, the statement over strategies that some trivial witness meets a pair with the theorem equating it with the class, the verdicts and the report.

**Not yet built**, each a separate issue of this repository: covering subject types in a higher universe, such as an agent that carries its own memory type, in this check and the degenerate check (#43); and holding the scripts of timed actions whose clock sits inside an argument or is the subject's only argument (#46).

The pair obligation ([pairs](pairs.md)) asks that each input a pair's precondition admits be served by some implementation, and lets the implementation depend on the input. So a pair can meet it through witnesses that do none of the work it is meant to ask for: in the worked example of the pairs, each legible world is reached by an agent that ignores what it sees, as a script timed in advance solves each feasible goal, while no such agent reaches the goal of every legible world. The method asks of each pair that no trivial witness meet it: an implementation that fixes its answers to the input in advance (a table, or a script of timed actions), one that ignores the input, and one that meets the postcondition only because the precondition admits nothing or the postcondition holds emptily. This check states, as theorems, which members of a closed class of them meet a pair, for the subject types the library's codes cover; it does not yet hold every script of timed actions (#46).

## The class

A witness is a strategy: the subject an implementation offers at each input of the pair. For a pair about subjects of a covered type `W` (`LeanIntent.Covered`: built-in types, function types, and the structures and inductive types a project declares, as the [degenerate check](degenerate-subjects.md) covers them, recursive, nested and mutual declared types following #23), of code `a₁ → … → aₙ → b`, the class `witnesses W` holds these members (`LeanIntent.Witness`), each with what it meets stated over strategies:

| Member | The strategies it stands for | Meets the pair exactly when | Theorem |
|---|---|---|---|
| `.vacuous` | Every strategy | Every subject meets it: the precondition admits no input, or the postcondition holds of every subject at each input it admits | `Witness.vacuous_meets_iff`, `Witness.vacuous_meets_iff_post`, `Witness.vacuous_meets_of_admits_nothing` |
| `.table` | At each input, the constant function at a value of `b` fixed for that input in advance: a table, or a script that takes one action throughout | Some table from the pair's inputs to values of `b` meets it; so whenever one constant function, at any value of `b`, meets it | `Witness.table_meets_iff`, `Witness.table_meets_of_met`, `Witness.oPair_constant_iff` |
| `.blind i`, for each argument position `i` of a function of at least two arguments | At each input, a subject chosen for that input that does not read its argument at `i` (`Sig.Fn.Ignores`), as a script of timed actions reads its clock and not what it sees | Some such strategy meets it; so whenever one such subject, or `.table`, meets it | `Witness.blind_meets_iff`, `Witness.blind_meets_of_met`, `Witness.blind_meets_of_table`, `Witness.oPair_blindTo_iff` |
| `.fixed d`, for each member `d` of the degenerate class of `W` | One subject `d` stands for, offered at every input, so the same whatever the input | A subject of `d` meets it | `Witness.fixed_meets_iff`, `Witness.fixed_meets_of_met` |

A function of one argument that does not read it is a constant, so it has no `.blind` member: `.table` holds it. For a plain value, with no argument, every subject is a constant, so `.table`, which ranges over every value, meets every pair that some value serves at each input, while the degenerate class of a plain value holds only the values its rule `Ty.Small` admits: every value of a type with finitely many values (`Ty.small_of_finite`), and of a number, a string, a list or an array only its empty value. A subject reads none of its arguments when it is a constant (`Witness.blindTo_of_constant`), so each per-input member offers a subject at every input and is met whenever every subject meets the pair (`Witness.table_meets_of_vacuous`). No member meets a pair with an admitted input that no subject serves (`Witness.not_meets_of_unserved`), so none is met by every pair.

`Sig.mem_witnesses_iff` states the class apart from the list that computes it, and `Sig.length_witnesses` its size: two members, one for each argument of a function of at least two, and one for each degenerate member. `Pair.MetTrivially` states, over strategies and apart from the class, that some trivial witness meets the pair: every strategy does; a table from its inputs to values of `b`, offering the constant function at the value it gives each input, does; for a function of at least two arguments, a strategy whose every subject does not read one same argument does; or one subject of a degenerate member, offered at every input, does. `metTrivially_iff` equates it with some member of the class meeting the pair, so the class omits no witness the statement names.

The class takes no pair and no parameter other than `W`, through its code, so it is the same for every pair about `W`, whatever the pair's input type, precondition or postcondition. It takes no implementation class either: it asks whether the pair as stated is met by a witness that does no work, whatever class the pair obligation is proved in. The input type needs no code: the members chosen at each input quantify over it, and no member is built from it. A subject type that is not covered has no `Covered` instance, so Lean reports that it cannot synthesize one, and no verdict about a pair of that type can be stated: such a pair is refused, never passed. Among such types is every type in a higher universe, such as a structure with a field that is a type (an agent that carries its own memory type, #43).

## Verdicts and the report

`WitnessVerdicts q bs` is the check: its goals (`witnessVerdicts`) state, for each member in order, that it meets `q` where `bs` says `true` and that it does not where `bs` says `false`, so each verdict is part of a theorem's statement and proved, and a list of the wrong length is refused (`witnessVerdicts_correct`, against `intendedWitnessVerdicts`). A verdict of `false` on a member that meets the pair cannot be proved, so a pair a trivial witness meets never passes. `reported W bs` lists the members the verdicts report as meeting the pair, which under proved verdicts are exactly those that do (`mem_reported`), and it is empty exactly when no trivial witness meets the pair (`reported_eq_nil_iff`). A member the report names is a fact about the pair to be handled as the method handles a degenerate subject that meets a record: the pair, or the obligation proved of it, is no evidence that the implementation does the work that member does not, so the agents state the pair whose input the implementation must not know (often the pair whose only input is trivial) or tell the owner of the fork.

## Worked example

[`LeanIntentExamples/TrivialWitnesses.lean`](../LeanIntentExamples/TrivialWitnesses.lean): the agent of the pairs' worked example, of type `Bool → Bool`, takes one argument, so the verdicts of its pairs are about any subject, the table, the constants at `false` and `true` and the identity. The per-world pair, which meets the pair obligation in the class of agents that ignore what they see (`perWorld_blind`), is met by the table, and the check reports it (`perWorld_witnesses`, `perWorld_table_reported`): each legible world is reached by the constant of the action it needs, fixed to it in advance. No constant, and not the table, meets the pair whose only input is trivial (`whole_witnesses`). An agent with a clock, of type `Fin 2 → Bool → Bool`, takes two arguments, so the verdicts of its pairs are also about a member for not reading its clock and one for not reading what it sees. Each readable course alone is followed by a script of timed actions, so the per-course pair is met by the member that does not read what the agent sees (`perCourse_witnesses`), though no constant follows a course that needs two different actions; no timed script follows every readable course, so that member does not meet the pair whose only input is trivial (`wholeCourse_witnesses`). In both, the agent that does what it sees meets every pair and is reported, as it would be by the degenerate check.

## What is trusted

Besides [what the README lists](../README.md#what-is-trusted), [what the pairs trust](pairs.md#what-is-trusted) and [what the degenerate check trusts](degenerate-subjects.md#what-is-trusted) about the codes of covered types:

- That a witness the class leaves out is not one the owner needed to see. The class holds no witness that does not read a part of one argument, such as a field of a structure, one side of a pair or all of a history but its length, since the type does not say which part of an argument is what the subject sees; a subject type whose only argument is a clock has no member for a script that reads it (#46 tracks both); and a strategy that offers different kinds of degenerate subject at different inputs, such as the projection onto one argument at some inputs and onto another at others, is in no member unless every subject it offers is a constant or does not read one same argument. Where such a witness matters, the pair's own statement over a type that separates what the subject sees (an argument of its own) brings it into the class.
- That not reading an argument of the function a subject's code denotes is not reading that argument of the subject itself: the isomorphism through which the code stands for the type takes each argument through a bijection of its type, as the degenerate check's codes fix it. This is argued, not proved.
- That every pair of a record about a covered type has its verdicts stated: Lean refuses to state verdicts about a pair of a type the class does not cover, but nothing in the library requires verdicts of a pair, as nothing requires the pair obligation.
