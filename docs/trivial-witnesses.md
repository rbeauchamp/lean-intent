# The trivial witnesses of a pair

**The trivial-witness check** (`LeanIntent.witnesses`, `LeanIntent.WitnessVerdicts`): for a precondition-postcondition pair about a subject type the library's codes cover, a closed class of trivial witnesses fixed by the pair's subject type and never chosen per pair (any subject at all, a table fixed to each input in advance, at each input a subject that does not read one of its arguments, one degenerate subject at every input, and at each input a script of timed actions on each clock the subject's arguments hold), with a proved verdict for each on whether it meets the pair, so that one that does is reported rather than missed.

Modules: `LeanIntent/TrivialWitnesses.lean`, and `LeanIntent/Clocks.lean` for the clocks inside a subject's arguments.

**Complete in this version:** the class with the theorems that fix it, the statement over strategies that some trivial witness meets a pair with the theorem equating it with the class, the verdicts and the report, and the scripts of timed actions whose clock sits inside an argument or is the subject's only argument (#46).

**Not yet built**, a separate issue of this repository: covering subject types in a higher universe, such as an agent that carries its own memory type, in this check and the degenerate check (#43).

The pair obligation ([pairs](pairs.md)) asks that each input a pair's precondition admits be served by some implementation, and lets the implementation depend on the input. So a pair can meet it through witnesses that do none of the work it is meant to ask for: in the worked example of the pairs, each legible world is reached by an agent that ignores what it sees, as a script timed in advance solves each feasible goal, while no such agent reaches the goal of every legible world. The method asks of each pair that no trivial witness meet it: an implementation that fixes its answers to the input in advance (a table, or a script of timed actions), one that ignores the input, and one that meets the postcondition only because the precondition admits nothing or the postcondition holds emptily. This check states, as theorems, which members of a closed class of them meet a pair, for the subject types the library's codes cover; the scripts of timed actions it holds are those on the clocks below.

## The class

A witness is a strategy: the subject an implementation offers at each input of the pair. For a pair about subjects of a covered type `W` (`LeanIntent.Covered`: built-in types, function types, and the structures and inductive types a project declares, as the [degenerate check](degenerate-subjects.md) covers them, recursive, nested and mutual declared types following #23), of code `a₁ → … → aₙ → b`, the class `witnesses W` holds these members (`LeanIntent.Witness`), each with what it meets stated over strategies:

| Member | The strategies it stands for | Meets the pair exactly when | Theorem |
|---|---|---|---|
| `.vacuous` | Every strategy | Every subject meets it: the precondition admits no input, or the postcondition holds of every subject at each input it admits | `Witness.vacuous_meets_iff`, `Witness.vacuous_meets_iff_post`, `Witness.vacuous_meets_of_admits_nothing` |
| `.table` | At each input, the constant function at a value of `b` fixed for that input in advance: a table, or a script that takes one action throughout | Some table from the pair's inputs to values of `b` meets it; so whenever one constant function, at any value of `b`, meets it | `Witness.table_meets_iff`, `Witness.table_meets_of_met`, `Witness.oPair_constant_iff` |
| `.blind i`, for each argument position `i` of a function of at least two arguments | At each input, a subject chosen for that input that does not read its argument at `i` (`Sig.Fn.Ignores`), as a script of timed actions reads its clock and not what it sees | Some such strategy meets it; so whenever one such subject, or `.table`, meets it | `Witness.blind_meets_iff`, `Witness.blind_meets_of_met`, `Witness.blind_meets_of_table`, `Witness.oPair_blindTo_iff` |
| `.fixed d`, for each member `d` of the degenerate class of `W` | One subject `d` stands for, offered at every input, so the same whatever the input | A subject of `d` meets it | `Witness.fixed_meets_iff`, `Witness.fixed_meets_of_met` |
| `.timed k`, for each clock part `k` of the arguments the class reads as a clock (`Sig.clocks`, below) | At each input, a script of timed actions on `k` chosen for that input: a subject that reads only `k` (`Sig.Fn.ReadsOnly`), which is a function of `k`'s reading (`ArgClock.readsOnly_iff_script`) | Some such strategy meets it, which is when a table of scripts, one fixed for each input in advance, does; so whenever one such subject, or `.table`, meets it | `Witness.timed_meets_iff`, `Witness.timed_meets_iff_script`, `Witness.timed_meets_of_met`, `Witness.timed_meets_of_table`, `Witness.oPair_timedBy_iff` |

A function of one argument that does not read it is a constant, so it has no `.blind` member: `.table` holds it. For a plain value, with no argument, every subject is a constant, so `.table`, which ranges over every value, meets every pair that some value serves at each input, while the degenerate class of a plain value holds only the values its rule `Ty.Small` admits: every value of a type with finitely many values (`Ty.small_of_finite`), and of a number, a string, a list or an array only its empty value. A subject reads none of its arguments when it is a constant (`Witness.blindTo_of_constant`), and reads only any clock part (`Witness.timedBy_of_constant`), so each per-input member offers a subject at every input and is met whenever every subject meets the pair (`Witness.table_meets_of_vacuous`). No member meets a pair with an admitted input that no subject serves (`Witness.not_meets_of_unserved`), so none is met by every pair.

`Sig.mem_witnesses_iff` states the class apart from the list that computes it, and `Sig.length_witnesses` its size: two members, one for each argument of a function of at least two, one for each degenerate member, and one for each clock part the class reads as a clock. `Pair.MetTrivially` states, over strategies and apart from the class, that some trivial witness meets the pair: every strategy does; a table from its inputs to values of `b`, offering the constant function at the value it gives each input, does; for a function of at least two arguments, a strategy whose every subject does not read one same argument does; one subject of a degenerate member, offered at every input, does; or, for a clock part of the arguments whose reading does not determine them or that is a `LeanIntent.Clock α`, a table of scripts of timed actions on it, offering at each input the script that takes, whenever the part reads `n`, the action the table gives that input and `n`, does. `metTrivially_iff` equates it with some member of the class meeting the pair, so the class omits no witness the statement names.

The class takes no pair and no parameter other than `W`, through its code, so it is the same for every pair about `W`, whatever the pair's input type, precondition or postcondition. It takes no implementation class either: it asks whether the pair as stated is met by a witness that does no work, whatever class the pair obligation is proved in. The input type needs no code: the members chosen at each input quantify over it, and no member is built from it. A subject type that is not covered has no `Covered` instance, so Lean reports that it cannot synthesize one, and no verdict about a pair of that type can be stated: such a pair is refused, never passed. Among such types is every type in a higher universe, such as a structure with a field that is a type (an agent that carries its own memory type, #43).

## Clocks

A script of timed actions reads its clock and not what it sees. Lean's logic cannot ask which part of an argument a project means as its clock, so `LeanIntent.Clocks` fixes, from the subject's code, the parts that can be one, and gives the project one way to declare a part its clock where the code alone cannot tell.

A *clock part* (`ArgClock`) is a component of one of a function's arguments, reached along a path of the degenerate class that applies no function (`ArgPath` over `NoSource`): the argument itself, a component of one side of a pair, or a component of a field of a declared type with one constructor, such as a structure, each of any covered type, a number, a `Fin (n + 1)`, a machine integer or a structure alike; with a reading of that component (`ClockRead`): its value, of its own type, or, for a list or an array, its length or size, a number. `ArgClock.read` reads it from a tuple of arguments. A part that does not exist, such as the element of a list, a side of a sum, a field of a type with several constructors or what a function returns, has no such path, so Lean refuses to elaborate it and no declaration can name it. `ArgClock.all` lists every clock part (`ArgClock.mem_all`), from every component of each argument (`Ty.components`, `Ty.mem_components`) and every reading of each (`ClockRead.all`, `ClockRead.mem_all`). The class reads two kinds of them as clocks (`Sig.clocks`, `Sig.mem_clocks_iff`):

- **By the subject's type alone**, each clock part whose reading does not determine the arguments: two tuples of arguments read the same there and differ elsewhere (`ArgClock.determines_eq_false_iff`, from `ArgClock.determines_iff`). Among them are the length of an agent's history, of type `List Obs → Act`, the time field of a structure that also holds what the agent sees, whatever the time's type, and each whole argument of a function of two or more arguments none of which has one value. A subject that reads only such a part does not read the rest of its arguments, a real restriction, as not reading one argument is; where the part is in fact what the subject sees and the rest its clock, it is a subject that ignores its clock, as `.blind` holds for whole arguments, and its report is a true statement about the pair either way.
- **By the project's declaration**, each clock part that is a value of type `LeanIntent.Clock α` (`ArgClock.InClock`), a structure of one field, the tick, of any covered type `α`, which a project gives to the part of its subject's arguments it means as its clock. A part whose reading determines the arguments, such as the only argument of a policy of type `Nat → Act`, is all the subject reads: reading it as a clock makes every subject a script, and reading it as what the subject sees makes no subject one, and the type alone cannot tell the two apart. The type alone reads such a part as what the subject sees, so a policy of type `Nat → Act` whose number is in fact a clock has no script in the class, and its pairs are checked as if it saw that number; the declaration, a policy of type `Clock Nat → Act`, reads it as a clock, and every pair that a policy chosen for each input serves is then reported (`Witness.timed_meets_iff_served`). The tick inside it, which determines the arguments too and is no `LeanIntent.Clock`, adds no second member. Where the implementation's type keeps a plain number, the record states its pairs over the declared type, and the [refinement link](refinement.md) reads each implementation `f` of type `Nat → Act` as the subject `fun c => f c.tick` through its mapping.

The declaration is a part of the subject's type, so it is read wherever a pair about that type is stated, in every module that names the type, and it is the same for every pair about the type. That it is a type, and not an instance or an attribute, is a choice of the agent that implemented it: an instance can sit in a module the verdicts do not import, or be passed for one pair. A `LeanIntent.Clock α` in an argument where no clock part reaches it, inside a list's elements, an option, a sum, a declared type with several constructors or a function, is a declaration the class cannot read: `Sig.strayClock` finds it, and the check's goals for such a type are the one goal `False`, so it is refused, not passed with the declaration ignored (`not_witnessVerdicts_of_strayClock`). It looks only in the fields of values, never in a declared type's parameters, which hold no value except through the fields that use them, so a type whose parameter names `LeanIntent.Clock` and whose fields hold none is checked as any other.

The class does not hold a script whose clock is a part whose reading determines the arguments and is no `LeanIntent.Clock α`, as above; nor one whose clock the clock parts do not reach: inside a list's elements, an option, a sum, a declared type with several constructors, a recursive type or what a function returns, or a reading of a component other than its value, a list's length and an array's size. A pair stated over a type that holds such a clock where the clock parts reach brings its scripts into the class.

## Verdicts and the report

`WitnessVerdicts q bs` is the check: its goals (`witnessVerdicts`) state, for each member in order, that it meets `q` where `bs` says `true` and that it does not where `bs` says `false`, so each verdict is part of a theorem's statement and proved, and a list of the wrong length is refused, as is a type that holds a `LeanIntent.Clock` the class cannot read (`witnessVerdicts_correct`, against `intendedWitnessVerdicts`). A verdict of `false` on a member that meets the pair cannot be proved, so a pair a trivial witness meets never passes. `reported W bs` lists the members the verdicts report as meeting the pair, which under proved verdicts are exactly those that do (`mem_reported`), and it is empty exactly when no trivial witness meets the pair (`reported_eq_nil_iff`). A member the report names is a fact about the pair to be handled as the method handles a degenerate subject that meets a record: the pair, or the obligation proved of it, is no evidence that the implementation does the work that member does not, so the agents state the pair whose input the implementation must not know (often the pair whose only input is trivial) or tell the owner of the fork.

## Worked examples

[`LeanIntentExamples/TrivialWitnesses.lean`](../LeanIntentExamples/TrivialWitnesses.lean): the agent of the pairs' worked example, of type `Bool → Bool`, takes one argument, so the verdicts of its pairs are about any subject, the table, the constants at `false` and `true` and the identity. The per-world pair, which meets the pair obligation in the class of agents that ignore what they see (`perWorld_blind`), is met by the table, and the check reports it (`perWorld_witnesses`, `perWorld_table_reported`): each legible world is reached by the constant of the action it needs, fixed to it in advance. No constant, and not the table, meets the pair whose only input is trivial (`whole_witnesses`). An agent with a clock, of type `Fin 2 → Bool → Bool`, takes two arguments, so the verdicts of its pairs are also about a member for not reading its clock and one for not reading what it sees, and, last, the scripts of timed actions that read only the value of each argument, the clock's and then what it sees, neither of which determines the arguments. Each readable course alone is followed by a script of timed actions, so the per-course pair is met by the member that does not read what the agent sees and by the script on the clock (`perCourse_witnesses`), though no constant follows a course that needs two different actions; no timed script follows every readable course, so neither meets the pair whose only input is trivial, which the subject that reads only what it sees meets (`wholeCourse_witnesses`). In both, the agent that does what it sees meets every pair and is reported, as it would be by the degenerate check.

[`LeanIntentExamples/Clocks.lean`](../LeanIntentExamples/Clocks.lean): agents whose class held no script before the clock parts. An agent of type `List Bool → Bool` that acts on its history follows each readable course alone by a script on the history's length, so its per-course pair is reported (`perCourseH_witnesses`, `perCourseH_script_reported`), while no member meets its pair whose only input is trivial (`wholeCourseH_witnesses`), which the agent that does what it saw last meets (`lastSeen_follows`). An agent that sees a structure holding the time and what it sees has the script on each field, both of which meet its per-course pair as the projection onto what it sees does (`perCourseG_witnesses`). An agent that sees a view holding a `UInt64` time and what it sees has the script on the time, the only member that meets the pair asking it to answer an input bit at time `0` and its negation at time `1` while seeing the same thing, and the check reports it (`tick_witnesses`, `tick_script_reported`). A policy of type `Clock Nat → Bool` reads only its clock, so the script on it meets the pair that gives each policy one schedule to keep (`perSchedule_witnesses`), while the same pair about policies of type `Nat → Bool` reports nothing, since the type alone reads the number as what the policy sees (`perScheduleNat_witnesses`). A `LeanIntent.Clock` inside a list is refused (`stray_refused`).

## What is trusted

Besides [what the README lists](../README.md#what-is-trusted), [what the pairs trust](pairs.md#what-is-trusted) and [what the degenerate check trusts](degenerate-subjects.md#what-is-trusted) about the codes of covered types:

- That a witness the class leaves out is not one the owner needed to see. The class holds no witness that does not read one part of an argument and reads the rest, such as one field of a structure or one side of a pair, other than a whole argument (`.blind`) and a script of timed actions, which reads only its clock; no script whose clock the class does not read as one (the section on clocks says which); and no strategy that offers different kinds of degenerate subject at different inputs, such as the projection onto one argument at some inputs and onto another at others, unless every subject it offers is a constant, does not read one same argument, or reads only one same clock. Where such a witness matters, the pair's own statement over a type that separates what the subject sees (an argument of its own) or declares its clock (a `LeanIntent.Clock α` the clock parts reach) brings it into the class.
- That a project means as its clock the part to which it gives the type `LeanIntent.Clock α`, and that a part whose reading determines the arguments and is no `LeanIntent.Clock α` is what the subject sees, as the section on clocks says. A project that types what its subject sees as a `LeanIntent.Clock α` has every subject reported as a script; one that leaves its only clock a plain number has no script reported.
- That a code naming `LeanIntent.Clock` stands for `LeanIntent.Clock`: the class recognizes the declaration by the name in the code its deriving handler writes, which the audit of declared types' codes (`LeanIntent.CodeAudit`) checks for each declaration it is run on, as the degenerate check trusts its codes.
- That not reading an argument of the function a subject's code denotes, or reading only a clock part of its arguments, is not reading that argument, or reading only that part, of the subject itself: the isomorphism through which the code stands for the type takes each argument through a bijection of its type, as the degenerate check's codes fix it, which takes each component through a bijection of its own type, a list's length and an array's size to themselves and a declared type's fields to its representation's. This is argued, not proved.
- That every pair of a record about a covered type has its verdicts stated: Lean refuses to state verdicts about a pair of a type the class does not cover, but nothing in the library requires verdicts of a pair, as nothing requires the pair obligation.
