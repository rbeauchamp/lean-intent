# ADR-0004: Ratcheted ban on Lean comments (`NO-COMMENTS`)

## Status

Accepted

## Context

Code comments across `lean-intent`'s `.lean` files accumulated 6,804 comment lines (~26.1% of all Lean source lines; ~7,030 lines or 27.0% including collapsed blank lines; counted at commit `ab64562`, before `main` moved to Lean v4.36.0): mostly tautological docstrings restating types and definitions, alongside stale comments that drifted behind code changes and excuse comments that rationalized hacky or incomplete implementations (e.g., unnecessary `import all`, skipped generic explanations, hardcoded magic fuel bounds, and stringly-typed sentinels; tracked in #85–#95). Meanwhile, genuine architectural and TCB rationale belongs in durable documentation (`docs/` and `docs/adr/`) rather than scattered inside source files.

Removing all ~2,400 comments cleanly in one change would make a single pull request too large to audit and review carefully.

### Acknowledgments

Warm thanks to [Matt Pocock](https://github.com/mattpocock) for the excellent originating concept and prompt in his November 20, 2026 post (`https://x.com/mattpocockuk/status/2123798388227403983`), which contributed the four-category comment audit (`Tautology`, `Stale`, `Excuse` paired with follow-up issue filing, and `Decision Record` preserved in durable ADRs) together with the ratcheted comment-ban linter and repeatable `/delete-comment` workflow adopted here and maintained in [`rbeauchamp/lean-no-comments`](https://github.com/rbeauchamp/lean-no-comments).

## Decision

### Scope

- All four Lean comment forms are banned across every tracked `.lean` file (`git ls-files -z -- '*.lean'`, including `LeanIntent/`, `LeanIntentExamples/`, and `tools/`):
  - line comments (`-- ...`),
  - plain block comments (`/- ... -/`),
  - declaration docstrings (`/-- ... -/`), and
  - module docstrings (`/-! ... -/`).
- Non-Lean configuration and workflow files (`.no-mistakes.yaml`, `.github/workflows/check.yml`, `lakefile.toml`, `tools/no-comments.pin`, `.no-comments.json`) and Markdown documentation (`README.md`, `docs/`, `.github/pull_request_template.md`) lie outside `*.lean` scope (`.no-comments.json` sets `"exclude": []` so zero tracked `.lean` files are excluded): `.no-mistakes.yaml`'s timeout messages and `AGENTS.md` cite its config comments, and `check.yml` documents commit-pinned GitHub Action versions.

### Owning-system enforcement (`NO-COMMENTS` via `rbeauchamp/lean-no-comments` `v0.2.0`)

`NO-COMMENTS` reads every tracked `.lean` file through Lean's own frontend via the pinned compiled `no-comments` CLI ([`rbeauchamp/lean-no-comments`](https://github.com/rbeauchamp/lean-no-comments/releases/tag/v0.2.0), release `v0.2.0`), never through regexes or hand-rolled lexers.

- **Pinned distribution and zero-dependency preservation (`LAKE-CONFIG`).** [`tools/no-comments.pin`](../../tools/no-comments.pin) pins `VERSION=v0.2.0` alongside the SHA-256 digests for `no-comments-darwin-arm64` (`4c610e1b0f0f93f54e89f33acb13c5120ed4e7ecfc3bb5db85e562aba637fe2a`) and `no-comments-linux-x86_64` (`f1a5d5cee2214515f9d36d3bb7245beee3856c06a85f6593ac0b23c4a0c6941e`), and [`.no-comments.json`](../../.no-comments.json) declares workspace `.` (`toolPrefixes: ["tools/"]`, `exclude: []`, `ratchet: "tools/comment-ratchet.json"`, relying on v0.2.0 defaults for omitted `srcDir`, `lakeArgs`, and `excludePrefixes`). Because `tools/check.lean` invokes `no-comments` out of band and enforces `LAKE-CONFIG` before both full checks and `--comments` inventory runs, `lakefile.toml` adds zero `[[require]]` or `[[lean_exe]]` entries, keeping `LAKE-CONFIG`, `AXIOMS`, and `PROCESS` intact.
- **Fail-closed SHA-256 verification and caching.** `tools/check.lean` checks that `tools/no-comments.pin` and `.no-comments.json` (plus `tools/comment-ratchet.json` for `check`) are regular stage-0 files at those exact paths in Git's index (`parseGitIndexEntry_regular_iff`) and non-symlink regular files in the working tree. For binary resolution it inspects every directory prefix and final filename via non-following `symlinkMetadata` (rejecting symlinked components on both `NO_COMMENTS_BIN` and `.lake/cache/no-comments/<sha256>/no-comments`), selects the platform checksum tool directly (`shasum -a 256` on macOS, `sha256sum` on Linux), and always executes the verified copy staged in `.lake/cache/no-comments/<sha256>/no-comments`. When `NO_COMMENTS_BIN` is set (taken verbatim with no whitespace trimming or blank-value fallback to the cache), `tools/check.lean` rejects symlink components on the supplied path, copies the file into a `mktemp` staging file inside the verified cache directory, checks its SHA-256 against `tools/no-comments.pin` (failing closed on mismatch even when a valid cached binary already exists), sets `0755`, atomically renames it into place, and re-verifies every cache path component and the digest before execution. When `NO_COMMENTS_BIN` is unset, it re-verifies every cache directory prefix, regular-file metadata, and SHA-256 on cache hits, and on misses creates missing cache directory components without traversing symlinks, downloads via HTTPS TLS 1.2+ `curl` into a `mktemp` staging file inside that directory, verifies SHA-256 before `chmod 0755` and atomic `IO.FS.rename`, and re-verifies after rename. In CI, [`.github/workflows/check.yml`](../../.github/workflows/check.yml) parses and validates `tools/no-comments.pin` directly (single release pin, rejecting symlinks and malformed entries), downloads the pinned `linux-x86_64` binary into `$RUNNER_TEMP`, verifies it with `sha256sum --check --strict`, and exports `NO_COMMENTS_BIN`.
- **Formally verified core and native worker isolation.** `rbeauchamp/lean-no-comments` `v0.2.0` splits its pure decision core (`NoCommentsCore`, checked with `regula v0.15.0` `standard-logical`: `NoComments.Core`, `NoComments.Config`, `NoComments.RatchetCore`) from its thin CLI/Lake harness (`NoCommentsCLI`). In `NoComments.Core` (41 theorems resting solely on Lean's standard axioms), `scanTrivia_coverage`, `checkSlice_coverage`, `collectSyntax_coverage`, `collectRanges_coverage`, and `sourceOrder_mem_iff` prove total structural/well-founded traversal and full `[0, endPos)` byte accounting; `checkToken_ok_iff` characterizes literal/identifier/registered-symbol safety around `--` and `/-` sequences; `distinctCommentLines_exact` and `distinctCommentLines_unique` prove exact distinct line-interval union cardinality; and `firstOutOfOrder_eq_none_iff`, `sortFingerprints_count`, `missingFrom_count`, `missingFrom_isEmpty_iff`, and `missingFrom_both_isEmpty_iff` prove sortedness and multiset subtraction semantics. For execution, `no-comments` verifies `lean --version` (version and commit) matches the compiled binary, queries Lake environment/setup (`Lake.loadWorkspace`, `lake setup-file --no-build`, and tool import precompilation for `tools/`), and runs isolated compiled native per-file child workers (`--jobs` defaulting to `min(cpus, 4)`) using `Elab.async := false`, `debug.byAsSorry := true`, `warningAsError := false`, and `linter.all := false`.
- **Resource measurements (`v4.36.0`).** Before extraction (using in-repo `lean --run tools/check.lean --comments-module` three readers at a time), `NO-COMMENTS` alone took `47–49 s` at `5.46–5.52 GiB` peak RSS under `v4.35.0`, and on 2026-11-21 under `v4.36.0` on an Apple M5 Max (18 cores, 128 GiB, via `no-mistakes admit`) clean `lean --run tools/check.lean` took `330.65 s` peaking at `5.523 GiB` (`5,790,928 KiB`) during the comment readers (`--tests`: `125.28 s` / `3.065 GiB` clean, `126.07 s` / `3.059 GiB` built; `313 s` / `5.63 GiB` built `check.lean`). After migrating to compiled `no-comments v0.2.0` on the same machine on 2026-11-21 (`0.1 s` process-group RSS sampling through `no-mistakes admit`): clean empty-cache `lean --run tools/check.lean` (including downloading the `v0.2.0` binary) took `328.00 s` and peaked at `4.733 GiB` (`4,963,136 KiB` at `8.0 s` during `lake build --wfail`), built `lean --run tools/check.lean` took `312.22 s` and peaked at `2.535 GiB` (`2,658,528 KiB`), standalone `no-comments check` took `23.73 s` and peaked at `1.821 GiB` (`1,909,072 KiB` across 5 processes), and `lean --run tools/check.lean --tests` took `106.40 s` and peaked at `2.965 GiB` (`3,108,880 KiB`). The configured bounds in `.no-mistakes.yaml` (`9 GiB` / `1020 s` for `check.lean`, `6 GiB` / `420 s` for `--tests`) retain wide headroom above both `3 ×` measured duration and peak RSS.
- **Inventory for people and retired local skill.** Contributors inspect remaining comments via the guarded command `lean --run tools/check.lean --comments [<file>]` (which checks `LAKE-CONFIG`, Git-index/working-tree pin and config admission, and the pinned binary's SHA-256 before delegating to `no-comments inventory`), printing per-file counts and repository totals (or per-comment `<fingerprint> <kind> L<start>-L<end>` lines for one file). The `/delete-comment` workflow skill now lives in [`rbeauchamp/lean-no-comments`](https://github.com/rbeauchamp/lean-no-comments) (`skills/delete-comment/SKILL.md`), retiring the duplicate local `.agents/skills/delete-comment/SKILL.md`.

### Strict per-file downward-only ratchet (`tools/comment-ratchet.json`)

- **What the manifest records.** `tools/comment-ratchet.json` is a JSON array with one object for each file that still has comments: `{"file": "...", "comments": N, "lines": M, "fingerprints": ["...", ...]}`. `fingerprints` holds one 64-bit FNV-1a hex fingerprint for each remaining comment in ascending order with repeats, `comments` is their count, and `lines` is the number of distinct lines covered (`distinctCommentLines`).
- **A JSON array, not an object,** because `Lean.Json.parse` silently overwrites duplicate object keys. `RatchetCore.parseRatchetJson` refuses duplicate `file` entries, unknown or missing keys, zero/non-integer `comments` or `lines`, non-16-hex fingerprints, unsorted fingerprints, `comments` differing from `fingerprints.size`, and `RatchetCore.validateCheck` refuses entries naming untracked or excluded files.
- **Exact sync and downward-only monotonicity.** For every tracked `.lean` file, `RatchetCore.checkExactSync` enforces that the live comment fingerprints (as a multiset) and distinct line count match `tools/comment-ratchet.json` (zero comments and zero lines when omitted), so adding, editing, or deleting comments without tightening the manifest is refused. Against the merge base's manifest, `RatchetCore.checkMonotonicFile` verifies both `Core.missingFrom liveFps expFps` is empty (no new/edited fingerprint or increased multiplicity, and drained/removed files retain `0` entries) and `liveLines ≤ expLines`.
- **Fail-closed merge-base verification (no `--bootstrap`).** `tools/check.lean` verifies `tools/comment-ratchet.json` (along with `tools/no-comments.pin` and `.no-comments.json`) is a regular stage-0 file at that exact path in Git's index (`parseGitIndexEntry_regular_iff`) and a non-symlink regular file in the working tree. When `--base-ref <ref>` is passed explicitly, `tools/check.lean` forwards it verbatim; when omitted, `tools/check.lean` resolves exact default refs (`refs/remotes/origin/main` then `refs/heads/main` via `git show-ref --verify` and `git rev-parse --verify --quiet --end-of-options <ref>^{commit}`) so no tag can shadow a branch, and passes the resolved commit SHA to `no-comments check --base-ref <sha>`. `NoComments.Ratchet` then computes `git merge-base HEAD <ref>`, checks the merge base holds `tools/comment-ratchet.json` as a regular blob (`100644`/`100755`, `git cat-file -t` = `blob`), and fails closed (exit `1`) if the ref is unknown, `merge-base` fails (such as in a shallow clone — which is why [`.github/workflows/check.yml`](../../.github/workflows/check.yml) sets `fetch-depth: 0` on `actions/checkout`), or the merge base lacks `tools/comment-ratchet.json`. Because `tools/comment-ratchet.json` is already committed on `main`, `tools/check.lean` invokes `no-comments check` without `--bootstrap`.

### Accepted risk

- The fingerprint is not a cryptographic hash. It identifies a comment against accidental or casual substitution; a comment crafted to collide with a deleted fingerprint would pass, as would a change editing `tools/check.lean`, `tools/no-comments.pin`, or `.no-comments.json` itself. Both require a deliberate author and are visible in review.

## Consequences

- Deleting `/--` docstrings removes their documentation text from Lean LSP hover tooltips (declarations keep their hover signatures and `#print` output, as Lean v4.36.0's `elabPrint` / `printIdCore` does not consult docstrings) and other docstring consumers; module specifications and non-obvious design rationale must live in `docs/` and `docs/adr/`.
- Any documentation link referencing a removed module comment (such as `README.md`, `.no-mistakes.yaml`, and `docs/*.md`) must be updated in the same change that removes that comment.
- Once every entry in `tools/comment-ratchet.json` is drained to `[]`, the codebase will carry zero Lean comments and `NO-COMMENTS` enforces a total ban.
