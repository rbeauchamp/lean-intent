# ADR-0007: Term printing, canonicalization, meaning closure, and rendering internals

## Status

Accepted

## Context

The term-printing and rendering stack (`LeanIntent/Print.lean`, `LeanIntent/Print/Token.lean`, `LeanIntent/Print/Term.lean`, `LeanIntent/Print/RoundTrip.lean`, `LeanIntent/Print/Printable.lean`, `LeanIntent/Print/Canon.lean`, `LeanIntent/Print/Meaning.lean`, `LeanIntent/Render.lean`, `LeanIntent/Render/Text.lean`) relies on several non-obvious proof-architecture, lexer, and MetaM environment invariants recorded in comments removed across Wave 1 and `#101`.

## Decision

### Surface syntax, tokenization, formatting, and round-trip proof composition (`LeanIntent/Print.lean`, `LeanIntent/Print/Token.lean`, `LeanIntent/Print/RoundTrip.lean`)

- **`bare` and `esc` printing parameters (`LeanIntent/Print.lean`)**: `Print.print` takes `bare` (constants written without `@` when no in-scope binder has their name) and `esc` (extra name components escaped in `«...»`, such as reader-grammar tokens); neither choice changes what `parse` reads back.
- **Token spacing, escapes, lexer alignment, and `import all` (`LeanIntent/Print/Token.lean`)**: Tokens are space-separated except where `glue` writes them adjacent (after `(`, `{`, `[`, `⦃`, `@`, `.{` and before `)`, `}`, `]`, `⦄`, `,`, `;`, `.{`, as Lean requires for `.{`); string literals escape only `\\`, `\"`, and `\n`; `lexIdent` and `continues` mirror Lean v4.36.0's `Lean.Parser.identFnAux` and `Lean.Parser.isIdCont` using `Lean.isIdFirst` and `Lean.isIdRest` (`.` continues an identifier only before `isIdFirst` or `«`), with `esc` avoiding Lean token-table collisions; and `Print/Token.lean` uses `import all Init.Meta.Defs` because its lexer proofs reduce `isIdFirst` and `isIdRest`, whose bodies `Init.Meta.Defs` does not expose to a `module` file.
- **Lexer and precedence-parser round-trip composition (`LeanIntent/Print/Token.lean:593`, `LeanIntent/Print/RoundTrip.lean:288`, `LeanIntent/Print/RoundTrip.lean:428`, `LeanIntent/Print/RoundTrip.lean:713`, `LeanIntent/Print.lean:205`–`211`)**: `lex_render` (`LeanIntent/Print/Token.lean:593`) proves `lex (render esc ts) = some ts` for every list of well-formed tokens (`∀ t ∈ ts, t.WF`) and every escape policy `esc`, so `render esc` is injective on well-formed token lists. In `LeanIntent/Print/RoundTrip.lean`, each parser round-trip claim depends on suffix conditions restricting what trailing tokens `rest` may follow the printed tokens (`psLevel_prLevel` at lines `99`–`103` requires `rest.head? ≠ some .plus` at non-atom level precedence because `levelTail` at `LeanIntent/Print/Term.lean:88`–`90` consumes a trailing `+ k`, and `psUnivs_prUnivs` at lines `224`–`225` requires `rest.head? ≠ some .dotBrace` because `psUnivs` at `LeanIntent/Print/Term.lean:134`–`137` matches a leading `.{` when `us = []`). `claims` (`LeanIntent/Print/RoundTrip.lean:713`) proves by induction on `e : Expr`, for every scope `sc` and every `bare` policy, that token parsing recovers `e` at each of the four precedences (`LeanIntent/Print/RoundTrip.lean:428`–`443`) under the suffix predicates at `LeanIntent/Print/RoundTrip.lean:288`–`305`: `ClaimA` (`LeanIntent/Print/RoundTrip.lean:428`–`429`) yields `ArgOk sc e ts` (`atomStart ts = true`, and `psAtom` with fuel `4 * ts.length + 1 ≤ f` recovers `e` leaving `rest` whenever `rest.head? ≠ some .dotBrace`, excluding `.{`); `ClaimH` (`LeanIntent/Print/RoundTrip.lean:431`–`435`) requires valid argument token lists (`ArgsOk sc as tas`), a suffix `rest` that starts neither another argument (`atomStart rest = false`) nor `.{` (`rest.head? ≠ some .dotBrace`), and fuel `4 * (ts.length + tas.flatten.length) + 2 ≤ f` so `psSimple` reads `ts ++ tas.flatten ++ rest` back as `some (mkApps e as, rest)`; `ClaimS` (`LeanIntent/Print/RoundTrip.lean:437`–`439`) requires `FollowsSimple rest` (`rest` is empty or starts with `)`, `}`, `]`, `⦄`, `:=`, `;`, or `→`) and fuel `4 * ts.length + 2 ≤ f` so `psSimple` recovers `e` leaving `rest`; and `ClaimT` (`LeanIntent/Print/RoundTrip.lean:441`–`443`) requires `FollowsTerm rest` (`rest` is empty or starts with `)`, `}`, `]`, `⦄`, `:=`, or `;`, excluding `→`) and fuel `4 * ts.length + 3 ≤ f` so `psTerm` recovers `e` leaving `rest`. These suffix conditions are essential to the statements—for example, `psTerm` (`LeanIntent/Print/Term.lean:249`–`255`) reads the printed tokens for `Prop` (`[.kwProp]`) followed by `→ Prop` (`[.arrow, .kwProp]`) as the single arrow type `Prop → Prop` (`some (.forallE .anonymous (.sort .zero) (.sort .zero) .default, [])`) rather than stopping at `Prop`, even with sufficient fuel (`4 * ts.length + 3 = 7`). `parse_print` (`LeanIntent/Print.lean:205`–`211`) composes those two boundaries: from `print bare esc e = some s` (yielding token list `ts` via `pr bare [] e .term`), `pr_wf` (`LeanIntent/Print.lean:111`) establishes `WFs ts` so `lex_render esc ts` recovers `ts` from `s.toList`, and `(claims bare e []).2.2.2` instantiates `ClaimT` at empty scope `[]`, empty suffix `rest = []`, and fuel `4 * ts.length + 3`; `FollowsTerm []` holds vacuously because `[].head? = none` makes the universal premise `rest.head? = some t` impossible (`fun _ h => by simp at h` at `LeanIntent/Print.lean:209`), so `ts ++ [] = ts` gives `psTerm (4 * ts.length + 3) [] ts = some (e, [])` (`[].isEmpty = true` at `LeanIntent/Print.lean:18`), proving `parse s = some e` (from which `print_injective` at `LeanIntent/Print.lean:213`–`217` follows across arbitrary `bare`/`esc` choices).

### Non-vacuity of the closed term printer (`LeanIntent/Print/Printable.lean`)

- `Printable` is defined independently of the printer `pr` and proved equivalent to `(pr bare sc e p).isSome` (`pr_isSome_iff`). This rules out a vacuous printer that satisfies `parse_print` by refusing every input, while ensuring nothing outside the closed printable grammar is emitted.

### Binder canonicalization and metadata erasure (`LeanIntent/Print/Canon.lean`)

- Lean generates macro-scoped binder names (`a✝`) that surface syntax cannot write, and terms can shadow earlier binders or collide with root names of constants referenced in the body. `canon` renames only the binders it must. A binder keeps its name when that name is one component the printer can write and neither an enclosing binder nor the first component of a constant in the term has it (`keeps`), so `∀ n : Nat, True` keeps `n` although its body does not use it. Only a binder that cannot keep its name (macro-scoped, shadowing, or colliding with a constant's root) is changed: a `∀` binder with the default annotation whose body does not use its variable becomes `.anonymous` and is printed as an arrow, and any other takes its name without macro scopes when that can be kept, and else the first of `x`, `x_1`, `x_2`, ... that can (`pick`).
- `Expr.mdata` is stripped before printing because Lean's kernel treats `Expr.mdata data e` as definitionally equal to `e` and ignores binder names; `eraseNames_canon` proves canonicalization changes nothing else.

### Meaning closure (`LeanIntent/Print/Meaning.lean`)

- `meaning` reuses `LeanIntent.Cone.RefersTo` / `declRefs` directly rather than duplicating dependency rules: theorem proofs, opaque constant values, and mutual blocks of definitions/theorems/opaques are excluded because Lean's kernel ignores them.
- `refsVia` dispatches on `RefsMode` (`value | eqn (e : Expr) | typeOnly`): `.value` follows `declRefs (.defnInfo v)`, `.eqn t` substitutes a recursive definition's unfolding equation `t` (plus `v.type`) for its compiled body (`mem_refsVia_eqn`), and `.typeOnly` follows `v.type` alone (`mem_refsVia_typeOnly`) while equation discovery is pending (#90).
- `ctor_mem`, `induct_mem`, and `block_mem` prove that when `meaning` succeeds (`.ok out`), every unstopped constructor (`stop k = false`) of an included inductive, the unstopped inductive (`stop v.induct = false`) of an included constructor, and every unstopped member (`stop i = false`) of an included recursor's mutual block is in `out`; `meaning_unknown` and `meaning_fuel` (via `meaning_error` / `Gap.Holds`) prove soundness of both refusal cases, `meaning_within` proves `Within` on success, and `meaning_ok_iff` characterizes completeness (`(∃ out, meaning lookup eqn stop fuel roots = .ok out) ↔ (∀ c, Reach lookup eqn stop roots c → (lookup c).isSome) ∧ Within lookup eqn stop roots fuel`). `collect` tracks visited names in `Std.HashSet Name` and skips stopped or visited names via `nextActive` without consuming fuel, while `meaning` parameterizes `fuel : Nat` (passed from `Render.Text.definitions` using the current loop environment's constant count `env.constants.map₂.foldl (fun k _ _ => k + 1) env.constants.map₁.size + 1`).

### Rendering MetaM invariants (`LeanIntent/Render/Text.lean`)

- **Bounded fixpoint loop, environment refresh, and completion invariant (`LeanIntent/Render/Text.lean:586`–`640`)**: `definitions` runs up to `limit` passes, where `limit` is computed once from the initial environment `env₀`'s constant count plus one (`LeanIntent/Render/Text.lean:588`–`591`), maintaining `eqns : NameMap (Name × Expr)` of unfolding equations collected so far. Each pass refreshes `env` via `askingIn` (`LeanIntent/Render/Text.lean:592`, which calls `getEnv` in `LeanIntent/Loaded.lean:33`–`36`) because `unfoldEqn` (`getUnfoldEqnFor?`, `LeanIntent/Render/Text.lean:490`) mutates the `MetaM` environment when realizing equation declarations, recomputes `bound` from that refreshed `env`, and runs `meaning` (`LeanIntent/Render/Text.lean:596`–`603`) mapping each constant already in `eqns` to `.eqn t` (following a definition's type and equation), each uncollected recursive constant (`(recursionKind env h c).isSome`) to `.typeOnly` (following a definition's type alone while equation discovery is pending), and every other constant to `.value` (refusing `.unknown` or `.fuel` with an error). It then filters `out` into `todo` (`LeanIntent/Render/Text.lean:604`–`613`) for entries not yet in `eqns` that are `.defnInfo` declarations with `(recursionKind env h c).isSome` or non-propositional `.axiomInfo` entries with `wasOriginallyDefn env c && (← isRecursiveDefinition c)`. Text is emitted only on a pass where `todo.isEmpty` (`LeanIntent/Render/Text.lean:614`–`637`), after reading `env` for formatting (`LeanIntent/Render/Text.lean:615`): on that pass every reached `.defnInfo` in `out` with `(recursionKind env h c).isSome` already has its equation in `eqns` and was followed by `meaning` through `.eqn t` (`meaning_ok` at `LeanIntent/Print/Meaning.lean:285`–`288` characterizes `out` as the exact `Reach` closure under those equations outside `stopAt`), and `declSection` processes each entry in `out` in the order `meaning` returns them (formatting each declaration section, checking that each constructor's or recursor's inductive types are in `out`, failing closed on any unprintable declaration or non-propositional axiom so nothing is printed in part, and folding generated `match`/`casesOn` helpers and `LeanIntent` definitions in `.readable` form). When `todo` is non-empty, `definitions` calls `unfoldEqn` for each entry in `todo` and inserts its equation into `eqns` (`LeanIntent/Render/Text.lean:638`–`639`, failing if `unfoldEqn` rejects any entry); if all `limit` passes finish without `todo` becoming empty, it raises an error (`cannot print the definitions: unfolding equations exceeded constant bound`, `LeanIntent/Render/Text.lean:640`) rather than emitting partial output, so the iteration budget is a fail-closed runtime guard and convergence within `limit` is not claimed for every render.
- **Stopping traversal at the record constant and seeding `Meets`/`HoldsOf`**: `recordPart` inserts the record's own constant into `shown` (since its clauses are already printed statement by statement above) and seeds `roots` with `IntentRecord.Meets` and (whenever consequences are non-empty) `Consequence.HoldsOf` so the rendered document defines what meeting a record and holding of a record mean.
- **Matcher elaboration in `elaboratesTo` and typed `RefsMode` (#89, #90)**: Lean `v4.36.0`'s `mkMatcherAuxDefinition` (`src/Lean/Meta/Match/Match.lean`, lines 1089–1132) caches matchers in the module-local `matcherExt` extension (keyed on closure value, compile flag, and privacy), so re-elaborating a readable `match` can return an existing matcher constant on a cache hit in the same module, or compile a fresh auxiliary matcher constant on a cache miss (for example when rendering a `match` originally compiled in another imported module); re-elaboration is therefore not guaranteed to be structurally equal (`Expr.equal`) to the original matcher constant. `elaboratesTo` disables matcher relaxation by default (`allowMatch := false`, used by `printExact`) and compares `e1 := eraseNames (eraseMData e')` against `e2 := eraseNames (eraseMData e)` via `Expr.equal`; only when `allowMatch` and `holdsMatch env e` hold (`Reader.print`, `allowMatch := true`) does it fall back to `equalModuloMatch env e1 e2`, requiring structural equality across non-matcher nodes and allowing differing constants only when both pass `isMatcherCore env` and `Kernel.isDefEqGuarded env {} (.const c1 us1) (.const c2 us2)` (#89). In `definitions`, `RefsMode` (`value | eqn (e : Expr) | typeOnly`) makes the three traversal states explicit in place of the `.sort .zero` sentinel (#90).
- **Public-import and exposure guards in `unfoldEqn`, `definitions`, and `declSection` (#71)**: In `module` files, `unfoldEqn` (alongside `definitions` and `declSection` catching non-exposed recursive definitions exported as `.axiomInfo` via `wasOriginallyDefn` and `isRecursiveDefinition`, and checking `((env.setExporting false).find? c)`) refuses imported recursive definitions whose module lacks `public import`, naming `public import` as the direct remedy and distinguishing missing `public import` from missing `@[expose]` in the defining module (see [`README.md#module-files`](../../README.md#module-files)).
- **Two-phase split**: `LeanIntent.Render` holds only the `meta` syntax/command elaborators, delegating all rendering programs to `LeanIntent.Render.Text` ([ADR-0006](0006-declared-type-coding-and-code-audit-internals.md)).
- **Extension-loading enforcement (#63)**: Every `MetaM` definition in `LeanIntent.Render.Text` and every command elaborator in `LeanIntent.Render` begins with `LeanIntent.asking` or `LeanIntent.askingIn`, while `bareConsts`, `holdsMatch`, `equalModuloMatch`, `kernelReduction`, `kernelIsDefEq`, `recursionKind`, and `importedModule?` require `(_h : LeanIntent.Loaded env)`. Only `stopAt` remains a `READERS` `stateless` exception, backed by Lean `v4.36.0` citations in [ADR-0009](0009-environment-extension-loading-and-reader-guards.md).
- **`printExact` bare-constant fallback**: `printExact` tries `bareConsts env h` first (omitting `@` only for constants whose leading `∀` binders are all explicit) and falls back to `fun _ => false` (all `@`) if Lean does not elaborate the bare print back.
- **`baseOptions`, `readableOptions` escalation, and read-back admission boundary**: `baseOptions` forces `pp.funBinderTypes`, `pp.piBinderTypes`, `pp.letVarTypes`, `pp.proofs`, and `pp.deepTerms` to `true` (`pp.maxSteps := 1000000`, `format.width := 100`) regardless of ambient options so the delaborator attempts to print binder types, proofs, and deep terms in full for elaboration without an expected type; those options alone do not guarantee omission-free output, because Lean `v4.36.0`'s `delab` (`src/Lean/PrettyPrinter/Delaborator/Basic.lean:440`–`454`) checks `pp.maxSteps` and emits `omission .maxSteps` before checking `pp.deepTerms` or `pp.proofs`. The renderer's admission boundary is the read-back check in `Reader.print` (`LeanIntent/Render/Text.lean:158`–`164`), which runs `elaboratesTo` on each candidate print and rejects any attempt—including an elided or ambiguous one—that fails to reproduce the term, escalating through the four progressively explicit `readableOptions` tiers (default, then `pp.numericTypes`/`pp.structureInstanceTypes`, then `pp.numericTypes` with `pp.coercions`/`pp.fieldNotation`/`pp.structureInstances`/`pp.match` disabled, then `pp.explicit`/`pp.universes` with `pp.fieldNotation`/`pp.structureInstances`/`pp.match` disabled) before falling back to `printClosed`/`printExact`.
- **`leanLibDir` resolution, real-path boundary, and search-path trust assumption**: `leanLibDir` (`LeanIntent/Render/Text.lean:339`–`353`) resolves Lean's library directory `lib` from `Lean.searchPathRef` via `Init.Prelude` rather than `Lean.getBuildDir` (which points to the toolchain only inside the `lean` binary) and checks via `IO.FS.realPath` that each of the four `leanRoots` (`Init`, `Std`, `Lean`, `Lake`) exists at `lib/<root>.olean` with `(IO.FS.realPath file).parent == some lib` (`LeanIntent/Render/Text.lean:347`–`352`), rejecting missing root files and symlink redirection outside `lib` (failing closed on any mismatch, while a symlink whose target stays inside `lib` still passes that parent check). This retains the search-path trust assumption recorded in [`docs/rendering.md`](../rendering.md#what-is-trusted): a project that sets its process search path to a directory holding its own `Init.Prelude` and all four root `.olean` files has that directory treated as Lean's own libraries.
- **`consequenceText` unstopped record expansion**: `consequenceText` passes an empty `shown` set (`{}`) to `definitions` (unlike `recordPart`, which stops at the record constant), so a predicate stated through a record prints the record's value and changes whenever the record changes.

## Consequences

- In Wave 1, `Print/Printable.lean`, `Print/Canon.lean`, `Print/Meaning.lean`, and `Render.lean` were cleared to zero comments, and the plain `--` comments and `elaboratesTo` docstring were removed from `Render/Text.lean`; for #101, `Print.lean`, `Print/RoundTrip.lean`, `Print/Term.lean`, `Print/Token.lean`, and `Render/Text.lean` are cleared to zero comments and `tools/comment-ratchet.json` is drained to `[]`, with all decisions above documented here alongside `docs/rendering.md`.
