# ADR-0006: Declared-type coding, two-phase module split, handler internals, and code audit

## Status

Accepted

## Context

The declared-type coding pipeline spans `LeanIntent/Codes.lean`, `LeanIntent/Clocks.lean`, `LeanIntent/Declared.lean`, `LeanIntent/Declared/Handler.lean`, and `LeanIntent/CodeAudit.lean`. Several non-obvious module-system, kernel-reduction, security, and performance decisions were carried in inline `--` comments, drained comments from `Declared.lean`, and docstrings scheduled for removal.

## Decision

### Two-phase `meta` vs non-`meta` module split

- Under Lean's module system, a `meta` declaration can only be called by another `meta` declaration.
- The deriving handler (`LeanIntent/Declared/Handler.lean`) and rendering engine (`LeanIntent/Render/Text.lean`) must run both at elaboration time (via `meta initialize` / command elaborators) and post-build as ordinary programs (called by `LeanIntent.CodeAudit` and the post-build check readers).
- Therefore the implementations live without `meta` in `LeanIntent.Declared.Handler` and `LeanIntent.Render.Text`, while `LeanIntent.Declared` and `LeanIntent.Render` import them with `meta import` solely to register the deriving handler and elaboration commands.

### Recursive-group encoding and exhaustive path matching

- In `LeanIntent/Codes.lean`, a recursive group's `g` parameter encodes field data and argument types at fixed paths: `[j, c, 0]` holds the chain of non-recursive data fields for type `j`, constructor `c`; `[j, c, 1, f]` holds the argument domain type for recursive field `f`.
- In `LeanIntent/Declared/Handler.lean`, `r` holds only group type indices (`Ty.ref l`) and no field or parameter codes, so Lean's kernel (`Kernel.isDefEq`) decides `Ty.inhabited`, `Ty.grows`, and `Ty.growsAt` uniformly even under free type-parameter variables or metavariables.
- In `LeanIntent/Clocks.lean`, `Ty.paths` matches every constructor of `Ty` with no catch-all branch so that adding a new code former to `Ty` causes a compile-time exhaustiveness failure until its component paths are specified.
- **Recursive-group index-only invariant and `LeanIntent.Clock` refusal (#57)**: In `LeanIntent/Codes.lean`, a recursive group's types appear in `Ty.mu` / `Ty.muAt` only by their index (`Ty.ref l`), whereas each non-recursive field or recursive-field argument is encoded by its own code, which preserves declared type names. Any check deciding by a declared type's name in a code—as `LeanIntent.Clocks` does for `LeanIntent.Clock` (`Clock.codeName`)—therefore requires `Declared.recCodeWith` (`LeanIntent/Declared/Handler.lean`) to refuse a recursive type whose values reach that type as a type of its group (`Declared.clockName`, `Declared.isClockSort`, `Declared.reachedClock?`, `Declared.reachedClock?_eq_none_iff`, verified equal to `Clock.codeName` by `Clock.codeName_eq_clockName` because `Clocks` imports `Declared` and not the reverse). `reachedClock?` indexes `group` via checked `group[l]?` (`RG1012` panic-free), relies on Lean `v4.36.0`'s kernel rule that only an application headed by an inductive constant forms a nested group type (`is_nested_inductive_app` in `src/kernel/inductive.cpp:1011–1043`), and runs inside `recCodeWith` so both `deriving LeanIntent.HasCode` (`recCode`) and `LeanIntent.CodeAudit` (`checkAttestation`) share the exact same refusal. Because the refusal denies the recursive type a code, the refused type has no code wherever it occurs (including as a subject's result or under an unused parameter of another type).
- **Closed-form clock acceptance and completeness (#57)**: Beside the existing `Ty.strayClock` search, `LeanIntent/Clocks.lean` introduces the occurrence relation `Ty.NamedClock` (`Ty.namesClock_iff`, `Clock.namesClock_code`), closed acceptance predicates `Ty.clocksRead` / `Ty.fieldsRead` (accepting only the code itself, pair sides, and fields of one-constructor declared types), and path extraction `Ty.NamedClock.path?` / `fieldPath?` (`Ty.NamedClock.path?_of_clocksRead`, `fieldPath?_of_fieldsRead`, `Place.ArgPath.From`, `Place.ArgPath.exists_from`). `Sig.strayClock` checks `σ.args.any fun a => a.strayClock || !a.clocksRead` (preserving every existing `Ty.strayClock` refusal alongside the closed-form guard), establishing `Sig.read_of_strayClock_eq_false` and `timed_mem_of_namedClock` (`LeanIntent/TrivialWitnesses.lean`) so proved verdicts always include `Witness.timed` on every `LeanIntent.Clock` named in an argument's code.

### Attestation auditing (`checkAttestation`, `checkRecMaps`, `builtinHeads`)

- **Dynamic `builtinHeads` discovery**: `builtinHeads` reads `Ty` and `Atom` constructors from Lean's environment, computes their kernel WHNF denotation heads via `Kernel.whnf` (which works identically during elaboration and in extensionless `importModules` audit scripts), and classifies non-inductive results against an explicit closed allowlist (`Ty.decl` and `Ty.atom` verified via `Kernel.isDefEq`, `Ty.arrow` as a forall type, and `Ty.muAt` checking that both branches of its `Bool.rec` conditional reduce to inductive heads), failing closed with an error on any unrecognized constructor denotation so attestations cannot assign a second code to any built-in type or a definition reducing to one.
- **Unifier for discovery, kernel for trust**: `checkAttestation` uses fresh metavariables and Lean's unifier only to discover candidate `HasCode` instances, then validates the attested type, derived code, and forward constructor images exclusively via Lean's kernel (`Kernel.isDefEq`). Only the forward map of an `Iso` is compared, because an isomorphism's forward map uniquely determines its inverse.
- **Untrusted candidate lookup for mutual group maps**: Inside `checkAttestation`, looking up `ci.name.modifyBase (·.getPrefix ++ Name.mkSimple s!"to{l}")` supplies only a candidate hint for sibling types in a recursive group (preserving macro scopes on base names); acceptance is decided solely by kernel-checked constructor equations in `checkRecMaps`.
- **Self-audit at derivation time**: `LeanIntent/Declared/Handler.lean` runs `checkAttestation` immediately after elaborating each derived `HasCode` instance so the deriving handler never emits an attestation that `LeanIntent.CodeAudit` would later refuse.

### Reduction, extensionless-environment, scope, and naming internals

- **`whnf` → `Kernel.whnf` fallback in `checkRecMaps`**: MetaM `whnf` can stop short of reducing a recursive map applied to a constructor to `MuVal.base`/`MuVal.node` when a recursive field is a function; `checkRecMaps` falls back to `Kernel.whnf` in that case.
- **Manual `Nat.decLt` proof construction**: `checkRecMaps` constructs `r < A` proofs directly via `of_decide_eq_true (Nat.decLt ...)` with `mkApp` instead of typeclass synthesis, keeping the proof term independent of instances offered by the environment (`tools/codes.lean` now calls `enableInitializersExecution` before `importModules ... (loadExts := true)` per #63 so `CodeAudit.isCarrier` reads loaded instance and class extensions).
- **Extension-loading and carrier enforcement (#63)**: `CodeAudit.audit` begins with `LeanIntent.askingIn`, `isCarrier`, `diagnosticType`, and `requireCodes` begin with `LeanIntent.asking`, and `axiomsIn` requires `LeanIntent.Loaded env`. `CodeAudit.isCarrier` checks Lean's default-instance registrations for `HasCode` and `Covered` (`Lean.Meta.getDefaultInstances`, reading `defaultInstanceExtension` at `Lean/Meta/Instances.lean` lines `401–409`, `437–444`) as well as active ordinary-instance registrations in `Lean.Meta.instanceExtension` (`instanceNames.find? ci.name` at lines `82–85`, `95–103`, `284–305`, `367–379`), accepting an entry directly when its stored registration key (`entry.keys[0]?`) is `.const ``HasCode _` or `.const ``Covered _`—so ordinary instances whose type alias was marked `[irreducible]` after registration remain recognized—and otherwise falling back to `Lean.Meta.MetaM.run' {} {}` with `Lean.Meta.forallTelescopeReducing` and `Lean.Meta.isClass?` on `classExtension` (matching Lean's `checkNonClassInstance` at lines `271–276, 350` and handling `no_index`/unreduced root keys) under `withoutExporting`, specified together in `isCarrier_eq`, so non-instance definitions of class type and non-class registered instances are excluded while `@[default_instance]` carriers and active ordinary `HasCode`/`Covered` instances are included. Only `relevantIn`, `importers`, `generatedBy`, and `instMonadEnvEnvM` remain `READERS` `stateless` exceptions, backed by Lean `v4.36.0` citations in [ADR-0009](0009-environment-extension-loading-and-reader-guards.md).
- **Namespace-relative naming (`relIdent`) across generated commands (#72)**: `relIdent` (`Name.modifyBase (·.replacePrefix ns .anonymous)`) replaces `_root_ ++ ...` across `mkStandsAndInstance`, `mkRecHasCode` (`let rel := relIdent ns`), and `mkHasCode` (`isoName`) so generated instances, mutual definitions, and theorems resolve relative to the current namespace while preserving macro scopes on macro-declared types.
- **Recursive equation realization (`getEqnsFor?` and `mkEqIdent`, #72)**: Instead of naming `_root_ ++ toName k ++ s!"eq_{c.alt}"` or rewriting with `rw [to{k}]`, `mkRecHasCode` realizes each `act (toName k)`'s equation theorems via `Lean.Meta.getEqnsFor?` inside `withoutExporting` (covering private definitions in `module` files) and references `eqs[c.alt - 1]?` through `mkEqIdent` (an `_internal`/`eqLemma` macro-scoped `Syntax.ident` carrying `[.decl c []]` preresolution) in both `invToDefs` and `toInvAlts`.
- **Section scope isolation (`handler`, #73)**: `handler` clears `varDecls`, `varUIds`, `includedVars`, `omittedVars`, and `levelNames` inside `withScope` so enclosing section `variable`, `include`, `omit`, and `universe` declarations do not alter generated definitions, theorems, or instances.
- **Module-file visibility, `noncomputable` fallback, and `withoutExporting` self-audit (`Declared/Handler.lean`)**: For a non-public type in a `module` file, everything the handler generates receives a private name via `writtenName`. Lean's compiler (`Lean.Compiler.LCNF.toLCNFType`) reads program types in both the private scope and the public scope and rejects discrepancies when `LeanIntent.Codes` is publicly imported while the private code is not; `handler` therefore sets `isNoncomputable := true` for hidden types (skipping compiled code only where LCNF refuses it, except in `meta` sections where Lean requires compilation or errors), rejects commands mixing public and non-public types in one `deriving` clause, exposes generated codes/isomorphisms/recursive maps as definitions so importers can reduce them, and runs its `checkAttestation` self-audit inside `withoutExporting` so theorem proofs are visible.

### Linear-time lazy reverse-dependency collection (`LeanIntent/CodeAudit.lean`)

- In `CodeAudit.audit`, reverse dependencies (`dependents`) are needed only to report carriers of refused attestations. They are therefore computed lazily (`unless refused.isEmpty`), deduplicating each declaration's outgoing references with a per-declaration `Std.HashSet` (`once`) and prepending to `List`s (`c :: ...`) instead of copying `Array`s, keeping collection linear in the number of reached references (preventing the stall observed in #59).

## Consequences

- In Wave 1, `Declared.lean` is cleared to zero comments and inline `--` comments and stale pre-#50/#55 docstrings are deleted from `Declared/Handler.lean`, `CodeAudit.lean`, `Codes.lean`, and `Clocks.lean`, preserving each non-obvious kernel/MetaM invariant and performance choice here; the remaining docstrings in those four files stay tracked in `tools/comment-ratchet.json` for later drain waves. For #63, `CodeAudit.lean`'s module docstring and `isCarrier` / `isCarrier_eq` docstrings were also drained (lowering `CodeAudit.lean` from `33` comments / `175` lines to `30` comments / `80` lines) when `isCarrier` was updated to check registered default and ordinary instances alongside class recognition, with their rationale preserved in [`docs/degenerate-subjects.md`](../degenerate-subjects.md), this ADR, and [ADR-0009](0009-environment-extension-loading-and-reader-guards.md). For #57, the module docstrings and updated refusal/clock docstrings were drained from `Declared/Handler.lean` (`40` comments / `259` lines to `38` comments / `119` lines), `Clocks.lean` (`198` comments / `464` lines to `195` comments / `340` lines), and `TrivialWitnesses.lean` (`74` comments / `247` lines to `71` comments / `143` lines), with all durable rationale and TCB invariants preserved in [`docs/trivial-witnesses.md`](../trivial-witnesses.md), [`docs/degenerate-subjects.md`](../degenerate-subjects.md), [`skills/intent-first/SKILL.md`](../../skills/intent-first/SKILL.md), and this ADR.
