# ADR-0006: Declared-type coding, two-phase module split, handler internals, and code audit

## Status

Accepted

## Context

The declared-type coding and declared-machine coverage pipeline spans `LeanIntent/Codes.lean`, `LeanIntent/Clocks.lean`, `LeanIntent/Degenerate.lean`, `LeanIntent/Declared.lean`, `LeanIntent/Declared/Handler.lean`, `LeanIntent/Machines.lean`, `LeanIntent/MachineDeclared.lean`, `LeanIntent/MachineDeclared/Handler.lean`, and `LeanIntent/CodeAudit.lean`. Several non-obvious module-system, kernel-reduction, security, and performance decisions were carried in comments removed across Wave 1, `#63`, `#57`, `#43`, and `#101`.

## Decision

### Two-phase `meta` vs non-`meta` module split

- Under Lean's module system, a `meta` declaration can only be called by another `meta` declaration.
- The deriving handlers (`LeanIntent/Declared/Handler.lean`, `LeanIntent/MachineDeclared/Handler.lean`) and rendering engine (`LeanIntent/Render/Text.lean`) must run both at elaboration time (via `meta initialize` / command elaborators) and post-build as ordinary programs (called by `LeanIntent.CodeAudit` and the post-build check readers).
- Therefore the implementations live without `meta` in `LeanIntent.Declared.Handler`, `LeanIntent.MachineDeclared.Handler`, and `LeanIntent.Render.Text`, while `LeanIntent.Declared`, `LeanIntent.MachineDeclared`, and `LeanIntent.Render` import them with `meta import` solely to register the deriving handlers and elaboration commands.

### Recursive-group encoding and exhaustive path matching

- In `LeanIntent/Codes.lean`, a recursive group's `g` parameter encodes field data and argument types at fixed paths: `[j, c, 0]` holds the chain of non-recursive data fields for type `j`, constructor `c`; `[j, c, 1, f]` holds the argument domain type for recursive field `f`.
- In `LeanIntent/Declared/Handler.lean`, `r` holds only group type indices (`Ty.ref l`) and no field or parameter codes, so Lean's kernel (`Kernel.isDefEq`) decides `Ty.inhabited`, `Ty.grows`, and `Ty.growsAt` uniformly even under free type-parameter variables or metavariables.
- In `LeanIntent/Clocks.lean`, `Ty.paths`, `Ty.viewOf`, `Ty.fieldPaths`, and `Ty.namesClock` match every constructor of `Ty` with no catch-all branch so that adding a new code former to `Ty` causes a compile-time exhaustiveness failure until its component paths and clock occurrences are specified (`Ty.namesClock` ignores declared type parameters because parameters enter values only through fields in the representation).
- **High-priority exact `HasCode` instance (`LeanIntent/Degenerate.lean`)**: `instance (priority := high) [ExactCode α] : HasCode α` is tried before the structural `HasCode` instances so every type built solely from built-in `Ty` formers gets `Iso.ofEq` mapping each value to itself by definition.
- **Recursive-group index-only invariant and `LeanIntent.Clock` refusal (#57)**: In `LeanIntent/Codes.lean`, a recursive group's types appear in `Ty.mu` / `Ty.muAt` only by their index (`Ty.ref l`), whereas each non-recursive field or recursive-field argument is encoded by its own code, which preserves declared type names. Any check deciding by a declared type's name in a code—as `LeanIntent.Clocks` does for `LeanIntent.Clock` (`Clock.codeName`)—therefore requires `Declared.recCodeWith` (`LeanIntent/Declared/Handler.lean`) to refuse a recursive type whose values reach that type as a type of its group (`Declared.clockName`, `Declared.isClockSort`, `Declared.reachedClock?`, `Declared.reachedClock?_eq_none_iff`, verified equal to `Clock.codeName` by `Clock.codeName_eq_clockName` because `Clocks` imports `Declared` and not the reverse). `reachedClock?` indexes `group` via checked `group[l]?` (`RG1012` panic-free), relies on Lean `v4.36.0`'s kernel rule that only an application headed by an inductive constant forms a nested group type (`is_nested_inductive_app` in `src/kernel/inductive.cpp:1011–1043`), and runs inside `recCodeWith` so both `deriving LeanIntent.HasCode` (`recCode`) and `LeanIntent.CodeAudit` (`checkAttestation`) share the exact same refusal. Because the refusal denies the recursive type a code, the refused type has no code wherever it occurs (including as a subject's result or under an unused parameter of another type).
- **Closed-form clock acceptance and completeness (#57)**: Beside the existing `Ty.strayClock` search, `LeanIntent/Clocks.lean` computes inhabited root-reachability over a recursive group (`Ty.reachStep`, `Ty.treeReach`, `Ty.treeNamesClock`, and structural `Ty.pathNamesClock` mirroring `Ty.pathEmpty` in `Codes.lean` so kernel reduction stays definitional) and applies it uniformly to `Ty.namesClock`, `Place.treeStrayAt` / `Place.treeStray`, and the occurrence relation `Ty.NamedClock` (`Ty.namesClock_iff`, `Clock.namesClock_code`, constructors `muBase`, `muData`, `muArg`, `muAtBase`, `muAtData`, `muAtArg`), proving `Sig.strayClock_eq_false_of_not_namesClock` so unreachable mutual siblings, uninhabited constructors, non-growing dead components, and index chains never trigger false refusals. The closed acceptance predicates `Ty.clocksRead` / `Ty.fieldsRead` accept only the code itself, pair sides, and fields of one-constructor declared types, with path extraction `Ty.NamedClock.path?` / `fieldPath?` (`Ty.NamedClock.path?_of_clocksRead`, `fieldPath?_of_fieldsRead`) lifted to a specific argument position `i` (`Place.ArgPath.From`, `Place.ArgPath.exists_from`). `Sig.strayClock` checks `σ.args.any fun a => a.strayClock || !a.clocksRead` (preserving every existing `Ty.strayClock` refusal alongside the closed-form guard), establishing `Sig.read_of_strayClock_eq_false` and `timed_mem_of_namedClock` (`LeanIntent/TrivialWitnesses.lean`) so proved verdicts include `Witness.timed` at each exact argument position `i` for every reachable `LeanIntent.Clock` in `c.sig.args[i]` (including signatures with repeated argument types such as `Clock Nat → Clock Nat → Bool`).

### Attestation auditing (`checkAttestation`, `checkRecMaps`, `builtinHeads`, and generalized `CodeAudit`)

- **Dynamic `builtinHeads` discovery**: `builtinHeads` reads `Ty` and `Atom` constructors from Lean's environment, computes their kernel WHNF denotation heads via `Kernel.whnf` (which works identically during elaboration and in extensionless `importModules` audit scripts), and classifies non-inductive results against an explicit closed allowlist (`Ty.decl` and `Ty.atom` verified via `Kernel.isDefEq`, `Ty.arrow` as a forall type, and `Ty.muAt` checking that both branches of its `Bool.rec` conditional reduce to inductive heads), failing closed with an error on any unrecognized constructor denotation so attestations cannot assign a second code to any built-in type or a definition reducing to one.
- **Unifier for discovery, kernel for trust**: `Declared.checkAttestation` uses fresh metavariables and Lean's unifier only to discover candidate `HasCode` instances, then validates the attested type, derived code, and forward constructor images exclusively via Lean's kernel (`Kernel.isDefEq`). Only the forward map of an `Iso` is compared, because an isomorphism's forward map uniquely determines its inverse.
- **Machine attestations (`LeanIntent/MachineDeclared/Handler.lean`, #43)**: `MachineDeclared.refusal?` (requiring `LeanIntent.Loaded env` and checking `isStructure (env.setExporting false) indVal.name` so plain `inductive` declarations are refused at the shared admission boundary), `readRoles`, `mkIso` (building the forward map from three standalone `[reducible]` projection definitions emitted by `mkCoveredMachine`—`instCoveredMachineT.memory`, `instCoveredMachineT.initial`, and `instCoveredMachineT.step`—each with a `projShape` body recognized by `Render.projectionOf` rather than embedding raw `Expr.proj` nodes or referencing user field projections whose names are private when a field is `private`, so `Render.printExact` and `Render.declSection` print generated machine isomorphisms cleanly for every public structure with a public constructor across `public`, `protected`, and `private` field visibilities), `checkAttestation`, `mkCoveredMachine` (checking duplicate coverage inside the `[HasCode I] [HasCode O]` local context before emitting declarations), and `handler` cover structures carrying a `Memory : Type`, an initial memory, and a step `Memory → In → Out × Memory` (in either order for the last two fields, with `In` and `Out` types of `Type` naming no field) using panic-free pattern matching (`let #[mem, f1, f2] := fs`, `fvarId?`, `head?`, explicit `(0, 1, 2)`/`(0, 2, 1)` field role matching, and `RG1012`-clean destructuring). `MachineDeclared.checkAttestation` validates the attested type `T as` (at universe level zero, not refused by `refusal?`), re-reads `roles` via `readRoles`, and checks via `Kernel.isDefEq` that `α = T as`, `I = roles.input`, `O = roles.output`, and `MachineIso.to e (ctor as fields) = Machine.mk I O M a s`, which fixes the isomorphism by structure eta and forward-map uniqueness (argued, not proved).
- **Multi-kind `CodeAudit` (`Attestor`, `KindTag`, `Kind`, `Kind.check`, `kinds`, #43)**: `LeanIntent.CodeAudit.unattested` and `decide` are parameterized by `kinds : List Attestor` (`ctor`, `exempt`, `verified`), with `decide_eq_none_iff` and `verified_of_decide_eq_none` restated over every `k ∈ kinds`. `CodeAudit.decide` uses fuel `2 ^ 64` (exceeding a 64-bit address space), and `AttestedType` / `attestedTypes` abstract each constructor application's first argument over enclosing `fun`, `∀` (converted to `fun`), and `let` binders to preserve de Bruijn indices without dropping polymorphic types or leaving loose bound variables, rendered by `diagnosticType` with `pp.funBinderTypes`, `pp.piBinderTypes`, and `pp.letVarTypes` enabled. `Kind` carries pure data (`stands`, `ctor`, `tag : KindTag`) rather than a `MetaM` closure so its structure projections do not take an `Environment` under `READERS`, and `Kind.check` dispatches under `LeanIntent.asking` to `Declared.checkAttestation` or `MachineDeclared.checkAttestation`. `CodeAudit.kinds` always includes `Ty.Stands` (`.declared`) and includes `Machine.Stands` (`.machine`) whenever `lookupIn env ``Machine.Stands` is `some _`; environments that do not import `LeanIntent.Machines` declare no constructor of `Machine.Stands`, so omitting that kind there avoids lookup errors while leaving no attestation unread. `Finding` records the inductive proposition `stands`, `Outcome.refusal?` records the third component naming the inductive propositions whose constructors a refused declaration applies, and `generatedBy` exempts Lean `v4.36.0`-generated `rec`, `casesOn`, `recOn`, and (where constructors take proofs of the proposition, as for `Ty.Stands` though not `Machine.Stands`) `below` declarations only when declared in the same module as `stands`.
- **Untrusted candidate lookup for mutual group maps (`checkRecMaps`)**: Inside `Declared.checkAttestation`, sibling group maps come from the `candidate` hint beside the attestation (`ci.name.modifyBase (·.getPrefix ++ Name.mkSimple s!"to{l}")`, preserving macro scopes on base names) when present, or else are inferred from the first child of that type and checked against every child; candidates decide nothing by name and are accepted solely by kernel-checked constructor equations in `checkRecMaps`.
- **Self-audit at derivation time**: Both `LeanIntent/Declared/Handler.lean` and `LeanIntent/MachineDeclared/Handler.lean` run their `checkAttestation` immediately after elaborating each derived instance inside `withoutExporting` so neither deriving handler ever emits an attestation that `LeanIntent.CodeAudit` would later refuse.

### Reduction, extensionless-environment, scope, and naming internals

- **`whnf` → `Kernel.whnf` fallback in `checkRecMaps`**: In Lean `v4.36.0`, MetaM `whnf` can stop short of reducing a recursive map applied to a constructor to `MuVal.base`/`MuVal.node` when a recursive field is a function; `checkRecMaps` (`reduce` in `LeanIntent/Declared/Handler.lean`) therefore falls back to `Kernel.whnf` whenever `whnf` does not expose `MuVal.base` or `MuVal.node`.
- **Manual `Nat.decLt` proof construction**: `checkRecMaps` constructs `r < A` proofs directly via `of_decide_eq_true (Nat.decLt ...)` with `mkApp` instead of typeclass synthesis, keeping the proof term independent of instances offered by the environment (`tools/codes.lean` now calls `enableInitializersExecution` before `importModules ... (loadExts := true)` per #63 so `CodeAudit.isCarrier` reads loaded instance and class extensions).
- **Extension-loading and carrier enforcement (#63, #43)**: `CodeAudit.audit` begins with `LeanIntent.askingIn`, `isCarrier`, `diagnosticType`, `Kind.check`, `kinds`, and `requireCodes` begin with `LeanIntent.asking`, and `axiomsIn` requires `LeanIntent.Loaded env`. `CodeAudit.isCarrier` checks Lean's default-instance registrations for `HasCode`, `Covered`, and `CoveredMachine` (`Lean.Meta.getDefaultInstances`, reading `defaultInstanceExtension` at `Lean/Meta/Instances.lean` lines `401–409`, `437–444`, returning `[]` when a class is absent from the environment) as well as active ordinary-instance registrations in `Lean.Meta.instanceExtension` (`instanceNames.find? ci.name` at lines `82–85`, `95–103`, `284–305`, `367–379`), accepting an entry directly when its stored registration key (`entry.keys[0]?`) is `.const ``HasCode _`, `.const ``Covered _`, or `.const ``CoveredMachine _`—so ordinary instances whose type alias was marked `[irreducible]` after registration remain recognized—and otherwise falling back to `Lean.Meta.MetaM.run' {} {}` with `Lean.Meta.forallTelescopeReducing` and `Lean.Meta.isClass?` on `classExtension` (matching Lean's `checkNonClassInstance` at lines `271–276, 350` and handling `no_index`/unreduced root keys) under `withoutExporting`, specified together in `isCarrier_eq`, so non-instance definitions of class type and non-class registered instances are excluded while `@[default_instance]` carriers and active ordinary `HasCode`/`Covered`/`CoveredMachine` instances are included. Only `relevantIn`, `importers`, `generatedBy`, and `instMonadEnvEnvM` remain `READERS` `stateless` exceptions, backed by Lean `v4.36.0` citations in [ADR-0009](0009-environment-extension-loading-and-reader-guards.md).
- **Namespace-relative naming (`relIdent`) across generated commands (#72)**: `relIdent` (`Name.modifyBase (·.replacePrefix ns .anonymous)`) replaces `_root_ ++ ...` across `mkStandsAndInstance`, `mkRecHasCode` (`let rel := relIdent ns`), and `mkHasCode` (`isoName`) so generated instances, mutual definitions, and theorems resolve relative to the current namespace while preserving macro scopes on macro-declared types.
- **Recursive equation realization (`getEqnsFor?` and `mkEqIdent`, #72)**: Instead of naming `_root_ ++ toName k ++ s!"eq_{c.alt}"` or rewriting with `rw [to{k}]`, `mkRecHasCode` realizes each `act (toName k)`'s equation theorems via `Lean.Meta.getEqnsFor?` inside `withoutExporting` (covering private definitions in `module` files) and references `eqs[c.alt - 1]?` through `mkEqIdent` (an `_internal`/`eqLemma` macro-scoped `Syntax.ident` carrying `[.decl c []]` preresolution) in both `invToDefs` and `toInvAlts`.
- **Section scope isolation (`handler`, #73, #43)**: Both `Declared.handler` and `MachineDeclared.handler` clear `varDecls`, `varUIds`, `includedVars`, `omittedVars`, and `levelNames` inside `withScope` so enclosing section `variable`, `include`, `omit`, and `universe` declarations do not alter generated definitions, theorems, or instances.
- **Bounded BFS reachability (`reached`) and `addFun` compilation (`LeanIntent/Declared/Handler.lean`)**: `reached` bounds its BFS to `group.size` steps because each valid index `< group.size` enters `todo` at most once when marked in `seen`, returning `none` if `todo` is still non-empty so callers fail closed. `addFun` aligns with Lean's `compileDecl` (`Lean/Elab/PreDefinition/Basic.lean`): in `meta` scopes it marks declarations `meta`, in non-`meta` `noncomputable` sections it passes `logCompileErrors := false` so LCNF refusals leave declarations without compiled code rather than erroring, and it adds `.defnDecl` with `hints := .abbrev` plus `setReducibleAttribute`.
- **Module-file visibility, `noncomputable` fallback, and `withoutExporting` self-audit (`Declared/Handler.lean`, `MachineDeclared/Handler.lean`)**: `writtenName` and `handler` match Lean's `Lean.Elab.applyDerivingHandlers` (which runs a `module` file's deriving handler in the private scope whenever any type in the command is private) and `Lean.Elab.applyVisibility` (where commands without explicit visibility in the private scope declare private names), so for a non-public type in a `module` file everything either handler generates receives a private name via `Declared.writtenName`, and both handlers reject commands mixing public and non-public types in one `deriving` clause. Lean's compiler (`Lean.Compiler.LCNF.toLCNFType`) reads program types in both the private scope and the public scope and rejects discrepancies when `LeanIntent.Codes` is publicly imported while the private code is not; both handlers therefore set `isNoncomputable := true` for hidden types (skipping compiled code only where LCNF refuses it, except in `meta` sections where Lean requires compilation or errors), expose generated codes/isomorphisms/recursive maps/instances as definitions so importers can reduce them, and run their `checkAttestation` self-audit inside `withoutExporting` so theorem proofs are visible.

### Linear-time lazy reverse-dependency collection (`LeanIntent/CodeAudit.lean`)

- In `CodeAudit.audit`, reverse dependencies (`dependents`) are needed only to report carriers of refused attestations. They are therefore computed lazily (`unless refused.isEmpty`), deduplicating each declaration's outgoing references with a per-declaration `Std.HashSet` (`once`) and prepending to `List`s (`c :: ...`) instead of copying `Array`s, keeping collection linear in the number of reached references (preventing the stall observed in #59).

## Consequences

- In Wave 1, `Declared.lean` was cleared to zero comments and inline `--` comments and stale pre-#50/#55 docstrings were deleted from `Declared/Handler.lean`, `CodeAudit.lean`, `Codes.lean`, and `Clocks.lean`; for #63, `CodeAudit.lean`'s module docstring and `isCarrier` / `isCarrier_eq` docstrings were drained (`33` comments / `175` lines to `30` comments / `80` lines); for #57, module and updated refusal/clock docstrings were drained from `Declared/Handler.lean`, `Clocks.lean`, and `TrivialWitnesses.lean`; for #43, all four new Lean modules (`LeanIntent/Machines.lean`, `LeanIntent/MachineDeclared.lean`, `LeanIntent/MachineDeclared/Handler.lean`, `LeanIntentExamples/Machines.lean`) shipped with zero comments and stale docstrings were drained from `CodeAudit.lean` and `Degenerate.lean`; and for #101, all remaining legacy comments in `Declared/Handler.lean`, `CodeAudit.lean`, `Codes.lean`, `Clocks.lean`, `Degenerate.lean`, and `TrivialWitnesses.lean` (alongside every other tracked `.lean` file) are cleared to zero comments and `tools/comment-ratchet.json` is drained to `[]`, with all durable rationale and TCB invariants preserved in [`docs/trivial-witnesses.md`](../trivial-witnesses.md), [`docs/degenerate-subjects.md`](../degenerate-subjects.md), [`docs/machines.md`](../machines.md), [`skills/intent-first/SKILL.md`](../../skills/intent-first/SKILL.md), [ADR-0009](0009-environment-extension-loading-and-reader-guards.md), and this ADR.
