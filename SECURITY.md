# Security policy

Report a vulnerability privately through GitHub's [private vulnerability reporting](https://github.com/rbeauchamp/lean-intent/security/advisories/new), not in a public issue, pull request, or comment. Include the commit, your Lean toolchain, what fails or is bypassed, and the smallest reproduction, without accessing other people's systems or data.

A privately reportable vulnerability is a soundness bug or check/audit bypass in `LeanIntent`, `tools/check.lean`, or `tools/codes.lean`—such as a proof or check that accepts an invalid obligation, degenerate/trivial-witness verdict, refinement, confirmation, execution, or required-theorems claim, a bypass of `LAKE-CONFIG`, `LEAN-BUILD`, `LEAN-MODULE`, `AXIOMS`, `PROCESS`, `CODES`, `NO-COMMENTS`, `REGULA`, or `--tests`, or compiled library code or a check run that harms the machine running it. What the [README](README.md#what-is-trusted), [ADR-0001](docs/adr/0001-repository-checks-and-trusted-base.md#trusted-base-and-consequences) (with [ADR-0002](docs/adr/0002-test-listing-and-pinned-lean-tokens.md), [ADR-0003](docs/adr/0003-runtime-process-audit-and-exemptions.md), and [ADR-0004](docs/adr/0004-ratcheted-ban-on-lean-comments.md)), and each feature document list as trusted—such as Lean's kernel and its three standard axioms, metaprograms or project code executed during Lean elaboration, `import all` of library modules not blocked by Lake, the deriving handler's reading of a declared type's constructors in declaration order, `Lean.manualRoot` reading `LEAN_MANUAL_ROOT`, and the owner-confirmed correspondence between a record and the owner's intent—is outside this policy until the trusted base changes.

`lean-intent` has one maintainer ([@rbeauchamp](https://github.com/rbeauchamp)), so it promises no response time. Confirmed fixes land on `main` after review and validation; dependent projects tracking `rev = "main"` (as shown in [the README](README.md#using-it)) pick up fixes by running `lake update lean-intent` and keeping the updated `lake-manifest.json`, while projects pinned to a specific commit must also advance their `rev` in `lakefile.toml` before updating the manifest.
